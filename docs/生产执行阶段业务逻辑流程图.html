核心链路：派发 → 备料 → 领料 → 报工 → 入库 → 完工（非倒冲工艺）。倒冲工艺快捷路径：派发 → 报工（首道倒冲跳过领料）。其中退料是对领料的逆向操作，删除报工是对报工的逆向操作，两者均会触发 plan_status 回退。

2.2 状态触发条件一览

状态变化方向触发操作触发条件
未开始 → 已派发→ 正向dispatchAndGenerateCore审批通过 + 无资源冲突
已派发 → 已备料→ 正向领料完成回调首道工序全部领完（所有 issued >= required）
已备料 → 已派发← 逆向DELETE material_issue撤回领料后首道工序不再全部领完
已派发 → 生产中
（首道倒冲）		→ 正向createWorkReport首道工序 is_backflush=1，物料门控跳过领料检查，直接放行
已备料 → 生产中→ 正向createWorkReport首道工序已全部领完，任意工序首次报工（completed_quantity > 0）
生产中 → 已备料← 逆向DELETE work_report删除所有报工后 completed_quantity 归零
生产中 → 已完成→ 正向createWorkReport所有工序 completed >= planned
已完成 → 生产中← 逆向DELETE work_report删除报工导致有工序未完成
关键约束：plan_status 支持双向流转（正向推进 + 逆向回退），以确保业务可逆性。但 sales_order_detail.production_status 遵循单向递进原则，只进不退。
⚠️ 倒冲约束：已派发 → 生产中（跳过领料、跳过已备料）的路径仅当首道工序（step_number=1）设定为倒冲（is_backflush=1）时才允许。若首道工序非倒冲，必须先完成领料使 plan_status 变为已备料，方可报工。这是物料门控（齐套性检查）的核心逻辑——报工时系统检查首道工序的 is_backflush 字段，倒冲则跳过领料齐套检查直接放行，非倒冲则校验 issued_quantity >= required_quantity。

4.2 互锁规则说明

规则项说明
检查时机DELETE /material-issues/:id 事务内，查询领料明细后、执行库存回退前（B2 步骤）
检查逻辑从领料明细提取所有 step_number，取最小值 minStep；查询 work_report 表，条件为 production_order_number 匹配且 step_number >= minStep
拦截条件查询结果集非空（即领料工序或后道工序已有报工记录）
返回状态HTTP 409 Conflict
返回消息"无法撤回：生产单 {orderNo} 的以下工序已报工，请先删除报工记录再撤回：工序{N}({名称})[{报工单号}]、…"
解除方式在报工管理页面删除所有冲突的 work_report 记录（需 approval_status=草稿），再重新发起撤回
前端处理axios 拦截器捕获 409，自动显示 message.error（WEP 端 Ant Design）或 showToast（APP 端 Vant）
⚠️ 业务约束：工序间存在严格的前后依赖关系。如果领料工序（如工序1混炼）或其后道工序（工序2硫化、工序3修边）已经报工，说明物料已被消耗或正在生产，此时撤回领料会导致库存与在制品不一致，必须先行删除报工记录。
