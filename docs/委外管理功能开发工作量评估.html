委外管理功能 — 开发工作量评估

Seals MES System  |  2026年5月

一、功能概述

业务描述：管理生产工序委外加工全流程，从委外申请、委外订单、发料、收回、质检到结算的完整闭环。同时提供委外单价管理和退货入库功能，并支持移动端扫码发料和收回操作。

1.1 业务流程

生产工单/工序任务 → 生成委外申请
     │
     ▼ 转单
委外订单（审批后生效）
     │
     ├─▶ 委外发料（原料出库→供应商）
     │       │ 审批 → 确认发料（扣减库存）
     │       │ 支持分批追加发料
     │
     ├─▶ 委外收回（供应商→入待检仓）
     │       │ 确认收回（自动创建质检单）
     │       │ 支持分批追加回收
     │
     ├─▶ 委外质检（合格/不合格判定）
     │       │ 完成质检 → 合格品入下一工序仓/成品仓
     │
     ├─▶ 退货入库（质检合格品入库到线边仓/下一工序仓）
     │
     └─▶ 委外结算（按单价×数量计算，审核后可登记付款）

六、关键影响因素

因素影响说明
8个子模块、11张表⚠️ 增耗时子模块数量多，表结构复杂（4个主从结构），是系统中最庞大的业务域之一
全流程状态联动⚠️ 增耗时申请→订单→发料→收回→质检→退货入库→结算，各环节状态互锁（如收回后自动创建质检单、质检完成后自动入库），级联逻辑增加 Service 层复杂度约 3 天
库存事务一致性⚠️ 增耗时发料确认扣减库存、收回确认入待检仓、质检完成入下一工序仓、退货入库增加库存，4处库存写操作需在事务内完成，增加约 2 天
移动端API⚠️ 增耗时发料+收回各需移动端 controller（扫码/拍照/打印标签），增加后端约 3 天
分批操作⚠️ 增耗时发料和收回均支持分批追加，需维护已发/已收数量汇总，增加约 1 天
审批框架集成✅ 省时委外申请+订单复用 approval.service.ts 审批框架，不做自定义工作流，免去审批节点编排约 2-3 天
复用现有基础设施✅ 省时复用 useTableList/useColumnPreference/useModalDrag + exportToExcel/exceljs + documentNumber.service，减少重复编码
生产调度自动生成委外申请⚠️ 增耗时生产调度模块已实现自动生成委外申请（orderDispatch），需确保字段兼容，增加约 0.5 天联调
