全流程概述：销售订单和销售预测作为需求输入，经过MPS计算（考虑成品安全库存、现有库存、采购在途、生产在途），计算出各物料的净需求，生成生产计划。生产计划审批通过后进入MRP运算，通过BOM逐层分解计算所有层级物料的需求。MRP确认执行后，自动生成生产工单（含计划导入的生产单）和采购申请。生产工单审批后可生成备料任务单和生产任务单；采购申请审批后可转采购订单。新增：生产计划删除或反审批撤消时，自动回退关联的销售订单/销售预测状态（revertPlanSourceStatuses），确保源单据可重新纳入计划。整个链路实现从需求→计划→执行→回退的全闭环管理。

MPS计算要点：
  • 销售订单与销售预测按物料合并，同一物料取两者需求量的最大值，避免重复计算
  • 生产在途查询必须加 po.item_number = pp.item_number 条件，防止MRP展开的子件工单被误累加
  • 已入库数量通过入库单计入 finished_goods_inventory，生产在途必须扣除已入库部分避免重复
  • 所有查询均带 factory_id 多工厂隔离条件
  • 返回结果包含产品扩展信息：橡胶编号(rubber_compound_number)、班产定额(batch_production_quota)

层级操作库存表关键逻辑
Level 0成品写入-成品直接写入mrp_run_detail，net=planned_quantity，确保即使子件库存充足也能生成生产单
Level 1半成品/原料material_inventory查material_inventory(不查finished_goods_inventory，避免与MPS重复扣减)
Level 2+深层子件material_inventory同上，递归展开直到无BOM或净需求≤0，最大深度10层
MRP计算核心要点：
  • 广度优先BFS：按层级逐层处理，每层先归集需求再批量查询，大幅减少数据库查询次数
  • 成品特殊处理：Level 0成品 net_requirement = planned_quantity（不做供给扣减），确保成品生产单必定生成
  • 子件净需求公式：net = MAX(0, gross - (on_hand + wip + in_transit_po + pending_pr) + safety_stock)
  • 安全库存：优先取 material_inventory.safety_stock_quantity，fallback到 item_master.safety_stock_qty（需safety_stock_enabled='Y'）
  • business_scope决策：生产→action_type=生产，采购→采购，生产+采购→双源(生产+采购)，NULL按BOM判断
  • 净需求≤0不入detail：净需求≤0的物料不生成MRP明细行（成品除外），避免无意义数据

  • 子件跳过机制：通过解析 parent_item_number 判断是否为纯采购父项的子件，若是则标记 result_status='已跳过'
  • 计划导入：MRP执行后自动将源Production_plan的生成为production_order（按计划编号+物料编号去重），同时更新plan_status为'已加入任务'
  • 去重机制：计划导入前检查 production_order 是否已存在相同 production_number+item_number 的记录，避免重复生成
  • 净需求≤0的处理：标记 result_status='已跳过'，不生成任何单据
  • 事务保护：整个执行过程在一个数据库事务中，任何步骤失败自动回滚

十一、关键业务规则汇总

11.1 MPS计算规则

  • 需求合并：同物料取 MAX(预测需求, 订单需求)，避免重复计算
  • 净需求 = MAX(0, 毛需求 - 现有库存 - 采购在途 - 生产在途 + 安全库存)
  • 生产在途 JOIN 必须加 item_number 条件，防止子件工单误累加
  • 已入库数量已计入 finished_goods_inventory，生产在途必须扣除 inbound_quantity
  • 仅净需求 > 0 的物料才建议导入生产计划

11.2 MRP运行规则

  • 可选计划条件：approval_status=已审批, plan_status=待加入任务, mrp_status IS NULL
  • BOM分解采用广度优先BFS，最大深度10层
  • Level 0成品不做供给扣减，确保生产单必定生成
  • Level 1+子件查 material_inventory（不查 finished_goods_inventory）
  • action_type 决策逻辑：business_scope优先 → NULL时按BOM判断（有BOM=生产, 无BOM=采购）
  • 净需求≤0的Level 1+物料不写入detail行

11.3 MRP执行规则

  • 仅 run_status='已计算' 的MRP可执行确认
  • 双源物料(生产+采购)：用户可选纯采购，其BOM子件全部跳过
  • 净需求≤0的detail行标记为'已跳过'
  • 计划导入前检查去重：同一 production_number+item_number 不重复生成生产工单
  • 采购申请合并生成：所有采购行汇总到一张 purchase_req，明细逐行写入
  • 执行后更新源计划：mrp_status='已分解', plan_status='已加入任务'

11.4 生产计划删除与撤消规则（新增）

  • 删除：仅草稿状态可删除，删除前在事务内调用 revertPlanSourceStatuses 回退源单据状态，确保原子性
  • 撤消(反审批)：已审批计划反审批时，approval.service.ts 通过 onPlanReversed 回调自动回退源单据状态
  • 来源判断：通过查询 sales_order 表确认 source_order_number 是订单还是预测
  • 销售订单回退：明细 production_status→未加入计划, status→未开始；若订单下无其他明细在排产(待排产/计划中/生产中)，头 order_status→待执行
  • 销售预测回退：明细 status→未开始（仅 status=计划中 的行）
  • MPS来源回退：按 item_number 回退所有 status=计划中 的预测明细
  • 防御性检查：回退前检查是否还有其他计划关联同一源单据，避免误回退
  • 工厂隔离：UPDATE 均带 factory_id 条件（从计划记录中读取）

11.5 MRP单据删除与回退规则

  • 仅草稿状态的生产工单/采购申请可删除
  • 删除前检查关联：查询是否还有其他 production_order 或 purchase_req 关联同一计划编号
  • 删除后回退：若某计划编号无任何关联单据，回退其 plan_status='待加入任务', mrp_status=NULL
  • 采购申请的 production_number 可能为逗号分隔多个计划编号，需逐个检查
  • MRP运行记录仅'已取消'状态可删除

11.6 多工厂隔离规则

  • 所有查询和写入均带 factory_id 条件，通过 x-factory-id 请求头注入
  • HQ总部模式支持传 factory_id 查询参数覆盖隔离条件
  • factory_id 传递链：Production_plan → mrp_run → mrp_run_plan/mrp_run_detail → production_order/purchase_req
  • 跨工厂操作禁止：如宁国工厂计划不可被广州工厂MRP运行或导入
