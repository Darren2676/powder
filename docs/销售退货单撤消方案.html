1. 方案概述

销售退货单在"已确认"状态时，意味着退货已经入库完成（库存已增加、销售订单的退款数量已回写）。此时如果需要取消这笔退货，不能简单删除记录，必须逆向执行库存回冲和业务数据回退，以确保系统数据的完整性和一致性。

本方案为"已确认+已入库"状态的销售退货单提供完整的撤消能力，涵盖库存回冲、销售订单回写回退、状态流转等全链路操作。

设计原则：
  • 撤消操作必须在事务中完成，保证原子性
  • 库存流水不物理删除，标记"作废"保留审计轨迹
  • 批次库存扣减后为0则标记作废，否则更新数量
  • 汇总库存按（物料+仓库+质量状态）维度扣减
  • 销售订单的 refunded_quantity、return_status、shipping_status 必须联动重算

3. 撤消前置条件与阻止检查

3.1 前置条件

#条件不满足时提示
1退货单 status = '已确认'"只有已确认状态的退货单可以撤消"
2退货单存在（未物理删除）"退货单不存在"

3.2 撤消执行路径

根据 inbound_status 分两个路径：
  • 已入库：需执行完整库存回冲（步骤3a~3e）+ 销售订单回退（步骤4~5）+ 状态更新（步骤6）
  • 未入库/入库失败：跳过库存回冲，仅执行销售订单回退（步骤4~5）+ 状态更新（步骤6）

4. 撤消回冲逻辑详解

4.1 库存回冲（inbound_status = '已入库' 时执行）

4.1.1 查找退货入库流水

SELECT * FROM inventory_transaction WHERE source_number = :return_order_number AND source_type = N'退货入库' AND (status IS NULL OR status != N'作废')

根据退货单号 + 来源类型"退货入库"匹配所有未作废的库存流水记录。

4.1.2 查找退货入库生成的成品批次

SELECT * FROM finished_batch_inventory WHERE return_order_number = :return_order_number AND status = N'正常'

退货入库时会为每个明细行生成新的成品批次（FB-开头），此时需要扣减或作废这些批次。

4.1.3 扣减批次库存

条件操作SQL 逻辑
扣减后数量 ≤ 0 标记批次为"作废" UPDATE finished_batch_inventory SET status = N'作废' WHERE id = :id
扣减后数量 > 0 更新批次数量 UPDATE finished_batch_inventory SET quantity = :newQty WHERE id = :id
计算公式：newQty = batch.quantity - batch.initial_quantity（入库时 initial_quantity 即为入库数量）

4.1.4 扣减汇总库存

按（物料编号 + 仓库编号 + 质量状态）维度扣减 finished_goods_inventory：

UPDATE finished_goods_inventory SET quantity = CASE WHEN quantity - :qty < 0 THEN 0 ELSE quantity - :qty END, last_updated = GETDATE() WHERE item_number = :item_number AND warehouse_number = :warehouse_number AND quality_status = :quality_status

4.1.5 标记库存流水作废

UPDATE inventory_transaction SET status = N'作废', void_operator = :operator, void_date = GETDATE() WHERE source_number = :return_order_number AND source_type = N'退货入库' AND (status IS NULL OR status != N'作废')
审计原则：库存流水不物理删除，仅标记"作废"并记录作废操作人和作废时间，保留完整审计轨迹。

4.2 销售订单回写回退

4.2.1 回退 refunded_quantity

退货确认时，系统将退货数量累加到 sales_order_detail.refunded_quantity。撤消时需逆向扣减：

UPDATE sales_order_detail SET refunded_quantity = CASE WHEN ISNULL(refunded_quantity, 0) - :qty < 0 THEN 0 ELSE ISNULL(refunded_quantity, 0) - :qty END WHERE id = :sales_detail_id

4.2.2 重算 return_status

调用 syncReturnStatus(sales_detail_id, transaction) 服务函数，根据最新的 refunded_quantity 重新计算退货状态。

4.2.3 重算 shipping_status

根据更新后的 shipped_quantity 和 refunded_quantity，重新计算发货状态：

条件shipping_status
净发货量 > 订单数量超额发货
净发货量 = 订单数量全部发货
0 < 净发货量 < 订单数量部分发货
净发货量 = 0 且有发货申请全部发货 / 部分发货（取决于申请量）
净发货量 = 0 且无发货申请未申请
净发货量公式：netShipped = shipped_quantity - refunded_quantity

4.2.4 同步行状态与订单头状态

调用 syncLineStatus(sales_detail_id, transaction) 服务函数，联动更新行状态和订单头状态。

4.3 退货单状态更新

UPDATE return_order SET status = N'已取消', inbound_status = CASE WHEN inbound_status = N'已入库' THEN N'已取消' ELSE inbound_status END WHERE return_order_number = :return_order_number

8. 完整撤消时序图

8.1 已入库退货单撤消

用户 → 前端: 点击"更多 → 撤消" 前端 → 前端: 弹出确认对话框（含库存回冲警告） 前端 → 后端: POST /return-orders/:rn/cancel 后端 → 数据库: BEGIN TRANSACTION 后端 → 数据库: SELECT * FROM return_order WITH (UPDLOCK) WHERE rn = :rn 后端 → 数据库: 校验 status = '已确认' alt inbound_status = '已入库' 后端 → 数据库: 查找 inventory_transaction（退货入库流水） 后端 → 数据库: 查找 finished_batch_inventory（退货批次） 后端 → 数据库: 逐批次扣减 quantity / 标记作废 后端 → 数据库: 扣减 finished_goods_inventory（汇总库存） 后端 → 数据库: 标记 inventory_transaction 为作废 end 后端 → 数据库: 查找 return_order_detail loop 每条退货明细 后端 → 数据库: 回退 sales_order_detail.refunded_quantity 后端 → 数据库: syncReturnStatus() 重算退货状态 end loop 每个关联的 sales_detail_id 后端 → 数据库: 重算 shipping_status 后端 → 数据库: syncLineStatus() 联动更新 end 后端 → 数据库: UPDATE return_order SET status='已取消' 后端 → 数据库: COMMIT TRANSACTION 后端 → 前端: { success: true, message: '退货单已撤消' } 前端 → 前端: message.success('退货单已撤消') 前端 → 后端: 刷新列表 fetchData()

9. 异常场景处理

#异常场景处理方式
1撤消时批次库存不足（已被其他出库消耗）quantity 扣减后为负数时，取 0 而非负值；汇总库存同理
2撤消时库存流水已被手动作废WHERE 条件排除 status='作废'，只处理有效流水
3入库失败但状态为已确认跳过库存回冲步骤（inbound_status≠'已入库'），仅回退销售订单数据
4撤消过程中数据库异常事务回滚，所有变更不生效
5并发撤消同一退货单UPDLOCK 行锁防止并发，第二次请求校验 status 已变更而失败
6refunded_quantity 扣减后为负CASE WHEN 限制下限为 0

10. 与发货单撤消方案的对比

对比项发货单撤消销售退货单撤消
可撤消状态待发货、已发货已确认
不可撤消状态已签收、已取消待确认、已驳回、已取消
库存操作方向回冲（加回库存）扣减（减去库存）
批次库存处理加回原出库批次数量扣减退货入库批次数量/作废
汇总库存处理syncFinishedGoodsSummaryCASE WHEN 扣减（下限0）
流水作废方向出库流水作废入库流水作废
销售订单回写shipped_quantity↓refunded_quantity↓
前置阻止检查退货单存在/已开票检查无额外阻止（仅状态校验）
箱码回退packing_box 状态回退无箱码关联
API 路由POST /shipping-orders/:sn/cancelPOST /return-orders/:rn/cancel
关键区别：发货单撤消是"加回库存"（出库→回冲），销售退货单撤消是"减去库存"（入库→逆向入库）。方向相反，但审计原则一致——流水不物理删除，仅标记作废。
