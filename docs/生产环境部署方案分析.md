# Seals MES 系统生产环境部署方案分析

## 1. 系统概述

| 项目 | 说明 |
|------|------|
| 后端框架 | Express.js + TypeScript |
| 前端框架 | Vue 3 + Ant Design Vue + Vite |
| 数据库 | SQL Server |
| 运行时 | Node.js |
| 开发环境 | Windows |

## 2. 方案对比

### 2.1 PM2 Cluster 模式

**原理：** PM2 在单机内启动多个 Node.js 进程（等于 CPU 核心数），由内置负载均衡器分发请求，充分利用多核 CPU。

**优势：**

- 部署简单，一条 `pm2 start` 即可启动，几乎零学习成本
- 单机多核利用，无需额外基础设施
- 自带进程管理、崩溃自动重启、日志管理、监控面板（`pm2 monit`）
- 与当前 `npm run dev` 开发模式接近，迁移无痛
- 对 SQL Server 连接友好，共享同一连接池配置
- 社区成熟，文档丰富，排障资料充足

**劣势：**

- 仅限单机，无法横向扩展到多台服务器
- 进程间内存隔离，不能共享会话状态（需外置 session/Redis）
- 集群内进程通信有限，WebSocket 需配置 sticky session
- 不提供环境隔离，依赖宿主机系统环境

### 2.2 Docker 容器化部署

**原理：** 将应用及其依赖打包为 Docker 镜像，以容器方式运行，通过 Docker Compose 或 K8s 编排多实例。

**优势：**

- 环境一致性（开发/测试/生产），消除"我机器上能跑"问题
- 可横向扩展，配合 Docker Compose / K8s 做多实例负载均衡
- 隔离性好，依赖、端口、文件系统互不干扰
- 便于 CI/CD 集成，镜像版本管理清晰，回滚便捷
- 未来迁移上云（K8s）的必要基础
- 前端可打包进 Nginx 容器，统一部署架构

**劣势：**

- 学习曲线较陡，需维护 Dockerfile + Compose 文件
- Windows 上 Docker Desktop 性能较差（磁盘 I/O 慢）
- SQL Server 在 Docker 中运行需 Linux 容器或独立部署
- 调试排障链路更长（需进入容器查看日志）
- 镜像构建和仓库管理增加运维复杂度
- 工厂内网环境可能无法访问外部镜像仓库

## 3. 详细对比

| 对比维度 | PM2 Cluster | Docker |
|----------|-------------|--------|
| **部署复杂度** | 低 | 中高 |
| **多核利用** | 支持（cluster 模式） | 支持（多容器） |
| **横向扩展** | 不支持 | 支持 |
| **环境隔离** | 无 | 强 |
| **进程管理** | 内置（自动重启/日志） | 需配置重启策略 |
| **学习成本** | 低 | 中高 |
| **CI/CD 集成** | 一般 | 优秀 |
| **SQL Server 兼容** | 原生支持 | 需独立部署或 Linux 容器 |
| **适用团队** | 传统 IT 运维 | DevOps 团队 |
| **上云就绪** | 否 | 是 |
| **工厂内网友好度** | 高 | 中（需私有仓库） |

## 4. 推荐方案

**当前阶段推荐 PM2 Cluster 模式**，理由如下：

### 4.1 系统规模匹配

MES 系统通常在工厂内网运行，用户规模在数十至数百人级别，单机 4-8 核完全足够支撑，PM2 cluster 已经能充分利用多核 CPU。当前无需多实例水平扩展。

### 4.2 SQL Server 依赖

当前系统强依赖 SQL Server，而 SQL Server 在生产环境通常是独立部署的物理机/VM。Docker 化应用层的收益被数据库层的非容器化削弱，整体架构变成"容器化应用 + 物理机数据库"的混合模式，增加运维复杂度但收益有限。

### 4.3 运维团队匹配

工厂 IT 团队更熟悉进程管理方式（类似 Windows 服务），对容器化概念接受度较低。PM2 的 `pm2 list`、`pm2 logs`、`pm2 restart` 等命令直观易懂，降低运维门槛。

### 4.4 快速投产

PM2 部署从零到上线可在半天内完成。Docker 方案需要编写 Dockerfile、构建镜像、配置网络和卷映射、搭建私有仓库等，投产周期更长。

## 5. PM2 生产配置

### 5.1 安装

```bash
npm install -g pm2
```

### 5.2 后端构建

```bash
cd server
npx tsc
```

### 5.3 前端构建

```bash
cd client
npx vite build
```

构建产物在 `client/dist/` 目录，由后端 Express 静态托管或独立 Nginx 托管。

### 5.4 ecosystem.config.js

> **Windows 限制：** PM2 cluster 模式在 Windows 上不支持端口共享（Linux 通过 `SO_REUSEPORT` 实现），多个 worker 同时监听同一端口会冲突。因此 Windows 开发环境使用 fork 模式（单进程），Linux 生产环境使用 cluster 模式（多进程）。

**Windows 开发环境（当前配置）：**

```js
module.exports = {
  apps: [
    {
      name: 'seals-mes-server',
      script: 'dist/server.js',
      cwd: './server',
      instances: 1,
      exec_mode: 'fork',
      max_memory_restart: '1G',
      env_production: {
        NODE_ENV: 'production',
        PORT: 3000
      }
    }
  ]
};
```

**Linux 生产环境：**

```js
module.exports = {
  apps: [
    {
      name: 'seals-mes-server',
      script: 'dist/server.js',
      cwd: '/opt/seals-mes/server',
      instances: 'max',
      exec_mode: 'cluster',
      max_memory_restart: '1G',
      env_production: {
        NODE_ENV: 'production',
        PORT: 3000
      }
    }
  ]
}
```

| 配置项 | 说明 |
|--------|------|
| `instances: 'max'` | 启动与 CPU 核心数相同的进程数 |
| `exec_mode: 'cluster'` | 集群模式，内置负载均衡 |
| `max_memory_restart: '1G'` | 内存超 1G 自动重启，防止内存泄漏 |

### 5.5 常用命令

```bash
# 启动
pm2 start ecosystem.config.js --env production

# 查看状态
pm2 list

# 查看日志
pm2 logs seals-mes-server

# 重启
pm2 restart seals-mes-server

# 停止
pm2 stop seals-mes-server

# 监控面板
pm2 monit

# 开机自启
pm2 startup
pm2 save
```

### 5.6 Nginx 反向代理（可选）

生产环境建议在 PM2 前加一层 Nginx，处理 SSL 终结和静态资源：

```nginx
server {
    listen 443 ssl;
    server_name mes.example.com;

    ssl_certificate     /etc/ssl/mes.crt;
    ssl_certificate_key /etc/ssl/mes.key;

    # 前端静态资源
    location / {
        root /opt/seals-mes/client/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 6. 未来演进路径

当以下条件出现时，可考虑迁移到 Docker/K8s：

- 用户规模增长，单机无法满足，需要多台服务器水平扩展
- 系统拆分为微服务架构
- 需要上云部署（阿里云/华为云等）
- 团队具备 DevOps 能力

迁移步骤：

1. 在 PM2 配置基础上添加 Dockerfile，应用代码无需改动
2. 使用 Docker Compose 编排应用 + Nginx
3. 逐步引入 K8s，实现自动扩缩容

## 7. 注意事项

- PM2 Cluster 模式下，文件上传（如附件）需使用共享存储目录，避免请求分发到不同进程导致文件找不到
- 定时任务（如 MRP 运算）需确保只在一个进程中执行，可使用 `pm2-ionice` 或应用层加锁
- 生产环境务必设置 `NODE_ENV=production`，Express 在此模式下性能更优
