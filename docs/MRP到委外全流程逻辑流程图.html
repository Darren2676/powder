MRP到委外全流程逻辑流程图

睿信橡胶密封件MES系统 | 从生产计划到委外结算的完整业务链路 | 2026-04-29 分批发料回收版
文档说明：本文档展示从MRP运算到委外结算的完整业务链路。重构 核心变更：委外订单审批后自动生成"待确认"单据（非已审核），全程使用material体系操作库存，新增待检仓→回收入库单环节，质检合格后才更新completed_quantity和order_status，增加报工阻断校验。新增 来料检验分流：根据 item_master.incoming_inspection 字段判断，'Y'走待检仓+质检流程，'N'免检直接入库到下道线边仓。新增 分批发料/分批回收：支持追加发料（appendIssue）和追加回收（appendReceipt），同一委外订单可创建多张出库/回收申请，累计校验不超过计划数量。

重构要点：
  • 转单不再自动生成发料单/收回单，改为委外订单审批后通过回调自动生成（status=待确认）
  • 全程使用material体系（material_batch_inventory/material_inventory/material_inventory_transaction），不再直接操作inventory表
  • 收回确认后入待检仓，质检合格后创建回收入库单（outsourcing_return_stockin）自动确认：待检仓出→下道线边仓入
  • completed_quantity在质检合格回收入库时才更新，确保WIP准确
  • 增加报工阻断校验：上一道工序为委外且未完成时拒绝报工
来料检验分流要点：
  • 确认收回时查询 item_master.incoming_inspection 字段
  • incoming_inspection='Y' → 入待检仓 + 创建质检单（原有流程不变）
  • incoming_inspection='N' → 免检直接入库：跳过待检仓和质检，直接创建回收入库单(已入库) + 入下道线边仓 + 更新completed_quantity + 更新order_status
  • 收回单 inspection_status 新增值：'免检'、'部分待检'（混合场景）
分批发料/分批回收要点：
  • 审批回调自动生成第一张全额出库/回收申请（status=待确认），适配最常见的单批场景
  • 分批场景通过追加发料（POST /outsourcing/issue/append）和追加回收（POST /outsourcing/receipt/append）创建额外申请
  • 追加发料：传入 batch_quantity，系统按 BOM × batch_quantity 预填明细
  • 追加回收：传入 receipt_quantity，系统累计校验 received_quantity + receipt_quantity ≤ planned_quantity
  • 同一委外订单可关联多张出库申请和多张回收申请，每张独立确认
  • 移动端返回 pending_issues/pending_receipts 列表，支持指定 issue_number/receipt_number 确认

决策要点：
  • MRP统一使用制造BOM（mfg_bom）而非设计BOM（bom）
  • action_type 由 item_master.business_scope 决定
  • 委外申请来源于工序任务的外协标识，非MRP直接生成

重构变更：

分批规则：
  • 审批回调自动生成第一张全额出库/回收申请（适配最常见的单批场景），用户可编辑减少数量
  • 分批场景通过"追加发料/追加回收"API创建额外的部分数量申请
  • 追加回收有累计校验：已回收数量 + 本次数量 ≤ 计划数量
  • 每张申请独立确认，确认后各自走完整的material体系库存操作
  • 多张回收申请各自触发来料检验分流，每张独立走质检或免检路径
  • 移动端返回 pending_issues/pending_receipts 列表，支持指定单号确认
  • 所有批次累计的 completed_quantity 达到 planned_quantity 时，order_status 变为"已完成"

  • 混合场景：同一收回单中部分物料需检验、部分免检，两条路径并行执行
收回单 inspection_status 新增值：
  • '待检验'：全部物料需检验
  • '免检'：全部物料免检
  • '部分待检'：部分需检验、部分免检

重要说明：委外订单有两个独立的状态维度：
  • approval_status（审批状态）：草稿 → 已审批。创建时为草稿，审批通过后变为已审批
  • order_status（执行状态）：待发出 → 已发出 → 部分收回 → 已完成 → 已关闭。创建时即为"待发出"
  • 发出确认需要 approval_status='已审批' AND order_status='待发出'，两个维度交叉约束
  • order_status 在质检合格回收入库时直接变为"已完成"（当qualified_quantity >= planned_quantity时），不再经过"已收回→已质检"的中间状态

十一、关键业务规则汇总

11.1 MRP到委外的触发条件

  • MRP统一使用制造BOM（mfg_bom_header/mfg_bom_detail）进行运算
  • MRP生成生产单后，由调度派发创建工序任务
  • 只有工序类型为"外协"的工序任务，才会触发委外申请
  • 委外申请审批通过后，转单为委外订单（草稿状态）
  • 委外订单审批通过后，回调自动生成备料出库申请（待确认）和委外回收申请（待确认）

11.2 备料出库规则

  • 审批回调自动创建备料出库申请，status=待确认，doc_type=issue
  • 出库明细从制造BOM自动填充：物料编号、名称、规格、应发数量
  • 仓库确认出库（WEB/移动端）后，使用material体系FIFO扣减线边仓
  • 同步material_inventory汇总表，记录material_inventory_transaction出库流水
  • 记录线边仓流水（direction=OUT）
  • 更新出库单status=已出库

11.3 回收与质检规则 来料检验分流

  • 审批回调自动创建委外回收申请，status=待确认，doc_type=receipt
  • 回收明细从委外订单产品信息自动填充，含待检仓和下道工序信息
  • 确认收回时查询 item_master.incoming_inspection 字段进行分流：
    • incoming_inspection='Y'（需检验）：入待检仓（material体系）→ 自动创建质检单（仅含需检验物料）→ inspection_status='待检验'
    • incoming_inspection='N'（免检）：跳过待检仓和质检，直接创建回收入库单(已入库) + 入下道线边仓 → inspection_status='免检'
    • 混合场景：部分物料需检验入待检仓、部分免检直接入库 → inspection_status='部分待检'
  • 回收确认后不更新 process_task.completed_quantity（需检验路径）
  • 免检路径在确认收回时立即更新 process_task.completed_quantity 和 outsourcing_order.qualified_quantity + order_status
  • 需检验路径：质检合格/让步接收 → 创建回收入库单 → 自动确认 → 待检仓出+线边仓入 → 此时更新completed_quantity
  • 不合格品仅记录处理方式，不入库，不计入completed_quantity
  • 质检单仅包含需检验的物料（免检物料不生成质检明细）
  • 回收入库单（outsourcing_return_stockin）在两条路径下都会创建：
    • 需检验路径：质检合格后创建，自动确认
    • 免检路径：确认收回时直接创建，status=已入库，remark=免检直接入库

11.4 报工阻断规则

  • 报工时检查上一道工序是否为外协类型
  • 上一道工序为外协且 outsourcing_order.order_status ≠ '已完成' → 拒绝报工(403)
  • 上一道工序为外协且 order_status = '已完成' → 允许报工
  • 前端应同步提示：报工按钮置灰，显示"等待委外回收入库"

11.5 结算规则

  • 结算数量 = 质检合格数量（不合格不计费）
  • 结算金额 = 合格数量 × 合同单价
  • 支持分批付款，付款完成后更新订单 settlement_status

11.6 删除与取消规则

  • 草稿状态的申请/订单可直接删除
  • 已审批的单据需先反审（撤回审批）才能删除
  • 已出库的发料单不能删除
  • 反审委外订单时，已自动生成的出库申请/回收申请需人工处理

11.7 分批发料与分批回收规则 分批

  • 审批回调自动生成第一张全额出库申请和回收申请（status=待确认），适配最常见的单批场景
  • 分批发料：POST /outsourcing/issue/append，传入 outsourcing_order_number + batch_quantity
  • 分批回收：POST /outsourcing/receipt/append，传入 outsourcing_order_number + receipt_quantity
  • 追加发料按 BOM标准用量 × batch_quantity 预填明细，仓库可编辑后确认
  • 追加回收累计校验：received_quantity + receipt_quantity ≤ planned_quantity，超出时返回400错误并提示可追加的最大数量
  • 同一委外订单可关联多张出库申请和多张回收申请（1:N关系）
  • 每张申请独立确认，各自走完整的material体系库存操作
  • 多张回收申请各自触发来料检验分流（incoming_inspection判断），每张独立走质检或免检路径
  • 移动端GET返回 pending_issues/pending_receipts 完整列表，POST支持指定 issue_number/receipt_number 确认特定批次
  • 所有批次的 completed_quantity 累计达到 planned_quantity 时，order_status 自动变为"已完成"
