## 一、方案概述

### 1.1 业务背景

在MES系统中，成品从生产完工到最终发运给客户，需要经历入库、库存管理、出库三个核心环节。成品库管理是连接**生产端**与**销售端**的关键枢纽，需要实现：

- **生产完工入库** — 已完成的生产单产品入库到指定仓库
- **发货出库** — 已审核的发货申请从仓库出库并完成发货
- **库存追踪** — 实时掌握成品库存水位、进出流水

### 1.2 功能目标

建立完整的**成品库管理体系**，包含以下四大功能：

1. **成品库存总览** — 按物料+仓库维度展示实时库存，支持搜索/筛选/手动调整
2. **生产完工入库** — 从已完成的生产单批量入库，自动更新生产单入库状态
3. **发货出库** — 从已审核的发货申请批量出库，自动更新发货申请和销售订单状态
4. **库存流水记录** — 全量出入库流水查询，按类型/来源分类筛选

## 二、数据库设计

### 2.1 新增表：成品库存表（finished_goods_inventory）

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `id` | INT IDENTITY(1,1) | PK | 主键自增 |
| `item_number` | NVARCHAR(100) | NOT NULL | 物料编号 |
| `item_name` | NVARCHAR(200) | '' | 物料名称 |
| `specifications` | NVARCHAR(200) | '' | 规格 |
| `basic_unit` | NVARCHAR(50) | '' | 基本单位 |
| `product_drawing_number` | NVARCHAR(100) | '' | 产品图号 |
| `warehouse_number` | NVARCHAR(50) | NOT NULL | 仓库编号 |
| `warehouse_name` | NVARCHAR(200) | '' | 仓库名称 |
| `quantity` | DECIMAL(18,4) | 0 | 当前库存数量 |
| `last_updated` | DATETIME | GETDATE() | 最后更新时间 |
| `creation_date` | DATETIME | GETDATE() | 创建日期 |

**唯一约束（业务层面）：** 同一物料在同一仓库下只有一条库存记录（`item_number` + `warehouse_number` 组合唯一）。

### 2.2 新增表：库存流水记录表（inventory_transaction）

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `id` | INT IDENTITY(1,1) | PK | 主键自增 |
| `transaction_number` | NVARCHAR(50) | NOT NULL | 流水编号 (IT-YYYYMMDD-NNN) |
| `transaction_type` | NVARCHAR(20) | '' | 出入库类型：入库 / 出库 |
| `source_type` | NVARCHAR(50) | '' | 来源类型：生产入库 / 发货出库 / 手动调整 |
| `source_number` | NVARCHAR(50) | '' | 来源单号（生产单号或发货申请号） |
| `item_number` | NVARCHAR(100) | '' | 物料编号 |
| `item_name` | NVARCHAR(200) | '' | 物料名称 |
| `specifications` | NVARCHAR(200) | '' | 规格 |
| `basic_unit` | NVARCHAR(50) | '' | 基本单位 |
| `product_drawing_number` | NVARCHAR(100) | '' | 产品图号 |
| `warehouse_number` | NVARCHAR(50) | '' | 仓库编号 |
| `warehouse_name` | NVARCHAR(200) | '' | 仓库名称 |
| `quantity` | DECIMAL(18,4) | 0 | 变动数量（绝对值） |
| `before_quantity` | DECIMAL(18,4) | 0 | 变动前库存数量 |
| `after_quantity` | DECIMAL(18,4) | 0 | 变动后库存数量 |
| `operator` | NVARCHAR(100) | '' | 操作人 |
| `operation_date` | DATETIME | GETDATE() | 操作日期 |
| `remark` | NVARCHAR(500) | '' | 备注 |
| `creation_date` | DATETIME | GETDATE() | 创建日期 |

### 2.3 新增字段：生产单表（production_order）

| 新增字段 | 类型 | 默认值 | 说明 |
|----------|------|--------|------|
| `inbound_quantity` | DECIMAL(18,4) | 0 | 已入库数量 |
| `inbound_status` | NVARCHAR(20) | '未入库' | 入库状态 |

**入库状态枚举值：**

| 状态值 | 说明 | 触发条件 |
|--------|------|----------|
| 未入库 | 尚未入库 | 初始默认值 |
| 部分入库 | 部分数量已入库 | inbound_quantity < planned_quantity |
| 全部入库 | 全部数量已入库 | inbound_quantity >= planned_quantity |

## 三、API接口设计

### 3.1 成品库存列表

```
GET /api/finished-goods/inventory
```

**查询参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `page` | number | 否 | 页码，默认 1 |
| `limit` | number | 否 | 每页条数，默认 20 |
| `search` | string | 否 | 搜索关键字（匹配物料编号/名称/规格/图号） |
| `warehouse_number` | string | 否 | 按仓库筛选 |

**响应体：**

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "id": 1,
        "item_number": "P001",
        "item_name": "O型密封圈",
        "specifications": "30x20x5",
        "basic_unit": "个",
        "product_drawing_number": "DWG-001",
        "warehouse_number": "WH001",
        "warehouse_name": "成品仓库A",
        "quantity": 1500.0000,
        "last_updated": "2026-03-23T10:30:00",
        "creation_date": "2026-03-20T08:00:00"
      }
    ],
    "total": 45,
    "page": 1,
    "limit": 20,
    "summary": {
      "total_items": 28,
      "total_warehouses": 3,
      "total_quantity": 35600.0000
    }
  }
}
```

### 3.2 库存详情（含流水）

```
GET /api/finished-goods/inventory/detail
```

**查询参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `item_number` | string | 是 | 物料编号 |
| `warehouse_number` | string | 否 | 仓库编号 |

**响应体：** 返回库存记录 + 最近100条流水记录。

### 3.3 待入库列表（已完成的生产单）

```
GET /api/finished-goods/pending-inbound
```

**筛选条件：**

```sql
WHERE plan_status = '已完成'
  AND approval_status = '已审批'
  AND (inbound_status IS NULL OR inbound_status IN ('未入库', '部分入库'))
```

**响应数据额外计算字段：**

| 字段 | 计算方式 | 说明 |
|------|----------|------|
| `inbound_qty` | ISNULL(inbound_quantity, 0) | 已入库数量 |
| `pending_inbound_qty` | planned_quantity - inbound_qty | 待入库数量 |

### 3.4 生产完工入库

```
POST /api/finished-goods/inbound
```

**请求体：**

```json
{
  "warehouse_number": "WH001",
  "warehouse_name": "成品仓库A",
  "remark": "2026年3月批次入库",
  "items": [
    {
      "production_order_number": "P20260323001",
      "item_number": "P001",
      "item_name": "O型密封圈",
      "specifications": "30x20x5",
      "basic_unit": "个",
      "product_drawing_number": "DWG-001",
      "planned_quantity": 1000,
      "inbound_quantity": 0,
      "inbound_qty": 1000
    }
  ]
}
```

**事务内操作：**

1. 查询/创建库存记录 → 增加库存数量
2. 生成入库流水记录（IT-YYYYMMDD-NNN）
3. 更新生产单 `inbound_quantity` 和 `inbound_status`

### 3.5 待出库列表（已审核的发货申请）

```
GET /api/finished-goods/pending-outbound
```

**筛选条件：**

```sql
WHERE h.status = '已审核'
```

**数据来源：** `shipping_request_detail` JOIN `shipping_request`，取发货申请明细行。

### 3.6 发货出库

```
POST /api/finished-goods/outbound
```

**请求体：**

```json
{
  "warehouse_number": "WH001",
  "warehouse_name": "成品仓库A",
  "remark": "客户发货",
  "items": [
    {
      "request_number": "SR-20260323-001",
      "detail_id": 5,
      "sales_detail_id": 12,
      "item_number": "P001",
      "item_name": "O型密封圈",
      "specifications": "30x20x5",
      "basic_unit": "个",
      "product_drawing_number": "DWG-001",
      "ship_quantity": 500
    }
  ]
}
```

**事务内操作：**

1. 校验库存充足（不足则回滚并返回错误）
2. 扣减库存数量
3. 生成出库流水记录
4. 更新销售订单明细 `shipped_quantity` 和 `shipping_status`
5. 更新发货申请状态为"已发货"

### 3.7 库存流水记录列表

```
GET /api/finished-goods/transactions
```

**查询参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `search` | string | 搜索流水号/来源单号/物料编号/名称 |
| `transaction_type` | string | 入库 / 出库 |
| `source_type` | string | 生产入库 / 发货出库 / 手动调整 |

### 3.8 手动调整库存

```
POST /api/finished-goods/adjust
```

**请求体：**

```json
{
  "item_number": "P001",
  "item_name": "O型密封圈",
  "specifications": "30x20x5",
  "basic_unit": "个",
  "product_drawing_number": "DWG-001",
  "warehouse_number": "WH001",
  "warehouse_name": "成品仓库A",
  "adjust_quantity": -50,
  "remark": "盘亏调整"
}
```

**说明：** `adjust_quantity` 正数为增加库存，负数为减少库存。调整后库存不允许为负数。

### 3.9 仓库下拉选项

```
GET /api/finished-goods/warehouse-options
```

**数据来源：** `warehouse` 表中 `condition = '启用'` 的仓库记录。

| sales_order_detail | shipped_quantity += ship_quantity | 累计已发货 |
| sales_order_detail | shipping_status | 根据发货比例更新 |

## 五、业务规则与校验

### 5.1 入库校验规则

| 条件 | 说明 | 校验层级 |
|------|------|----------|
| 生产单状态 = "已完成" | 只有已完成的生产单才能入库 | 后端查询条件 |
| 审批状态 = "已审批" | 必须已审批 | 后端查询条件 |
| 入库状态 ∈ {未入库, 部分入库} | 已全部入库的不再显示 | 后端查询条件 |
| 入库数量 > 0 | 数量为0的行跳过 | 后端校验 |
| 仓库必选 | 必须指定入库仓库 | 前端 + 后端双重校验 |

### 5.2 出库校验规则

| 条件 | 说明 | 校验层级 |
|------|------|----------|
| 发货申请状态 = "已审核" | 只有已审核的发货申请才能出库 | 后端查询条件 |
| 库存 >= 出库数量 | 库存不足时拒绝出库并返回错误 | 后端事务内校验 |
| 仓库必选 | 必须指定出库仓库 | 前端 + 后端双重校验 |
| 出库数量 > 0 | 数量为0的行跳过 | 后端校验 |

### 5.3 手动调整校验规则

| 条件 | 说明 |
|------|------|
| 调整数量 ≠ 0 | 不允许0值调整 |
| 调整后库存 >= 0 | 不允许调整为负数 |
| 物料编号必填 | 必须指定物料 |
| 仓库必填 | 必须指定仓库 |

### 5.4 状态联动规则

**生产单入库状态更新：**

```
入库后 totalInbound = 原inbound_quantity + 本次inbound_qty

if totalInbound >= planned_quantity:
    inbound_status = '全部入库'
else:
    inbound_status = '部分入库'
```

**销售订单发货状态更新（出库时触发）：**

```
出库后 totalShipped = 原shipped_quantity + 本次ship_quantity

if totalShipped > order_quantity:
    shipping_status = '超额发货'
elif totalShipped == order_quantity:
    shipping_status = '全部发货'
else:
    shipping_status = '部分发货'
```

## 六、事务与异常处理

### 6.1 事务策略

所有入库/出库/调整操作均在同一个数据库事务（`sequelize.transaction()`）中执行：

| 操作 | 事务内步骤 |
|------|----------|
| 生产入库 | ① 更新/创建库存 → ② 生成流水 → ③ 更新生产单状态 |
| 发货出库 | ① 校验库存 → ② 扣减库存 → ③ 生成流水 → ④ 更新销售订单 → ⑤ 更新发货申请 |
| 手动调整 | ① 校验调整后不为负 → ② 更新/创建库存 → ③ 生成流水 |

### 6.2 容错机制

| 场景 | 处理方式 |
|------|----------|
| 库存记录不存在（入库） | 自动创建新库存记录 |
| 库存记录不存在（出库） | 返回错误信息：该仓库无此物料库存 |
| 库存不足（出库） | 返回错误信息：含当前库存和需出库数量 |
| 调整后为负数 | 返回错误信息：含当前库存 |
| 入库数量为0 | 跳过该行，继续处理其他行 |
| 数据库异常 | 事务回滚，所有更改撤销 |

## 七、编号生成规则

### 7.1 库存流水编号

```
格式：IT-YYYYMMDD-NNN
示例：IT-20260323-001, IT-20260323-002, ...
规则：查询当天最大编号，序号+1
范围：每天从001开始，最大支持999条/天
```

**生成逻辑：**

```sql
SELECT MAX(transaction_number) as max_num
FROM inventory_transaction
WHERE transaction_number LIKE 'IT-20260323-%'
```
