报销单管理功能 — 开发工作量评估

Seals MES System  |  2026年5月

一、功能概述

业务描述：员工新建报销单并填写费用明细，提交后进入多级审批流程（审批步骤和审批人可配置），审批通过后完成报销。系统自动计算报销总额、退回/补领金额，支持差旅费专用字段及附件上传。

1.1 流程状态机

员工新建 → 草稿
     │
     ▼ 提交（配置审批步骤）
待审批（step 1）
     │
     ▼ 审批通过（当前步骤）
审批中（step +1） ←──────┐
     │                    │
     ▼ 最后一步通过        │ 驳回
已审批                    │
     │                    ▼
     │               已驳回 ──重新提交──→ 待审批（重置步骤）
     │
     ▼ 撤回（仅申请人）
草稿

反审（仅 manager/admin）：已审批 → 草稿

1.2 结算自动计算

总额 = SUM(费用明细.amount)
若 总额 ≥ 预支金额：补领 = 总额 - 预支，退回 = 0
若 总额 < 预支金额：退回 = 预支 - 总额，补领 = 0

1.3 角色权限

操作申请人（staff）审批人管理人员（manager/admin）
新建报销单✅✅✅
编辑（草稿/已驳回）✅（本人）❌❌
提交审批✅（本人）❌❌
审批通过/驳回❌✅（当前步骤审批人）❌
撤回✅（本人）❌❌
反审❌❌✅
删除（仅草稿）✅（本人）❌❌

六、关键影响因素

因素影响说明
自定义多级审批流⚠️ 增耗时不复用现有 approval.service.ts 三态框架（仅支持草稿→待审批→已审批），需独立实现步骤配置+流转+驳回+撤回逻辑，约 +2.5天
可编辑明细表格⚠️ 增耗时详情页需支持行内新增/编辑/删除费用明细，交互复杂度高于纯展示，约 +1天
差旅费专用字段⚠️ 增耗时同一明细表中差旅费行有额外字段（起止地点/交通工具/人数/天数/补贴标准），前端需条件渲染，约 +0.5天
附件上传⚠️ 增耗时需对接现有 upload.middleware.ts（multer），增加附件表CRUD，约 +0.5天
无需控资金流✅ 省时不对接支付/银行接口，结算闭环仅做金额计算记录
复用 composable✅ 省时列表页直接复用 useTableList + useColumnPreference
复用 upload 模块✅ 省时附件上传直接使用项目已有的 upload.middleware.ts，无需从零开发
无移动端适配✅ 省时基础方案不含 client-mobile
