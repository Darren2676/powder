## 一、方案概述

### 1.1 业务背景

在MES系统中，生产单从创建到执行需要经历一个完整的审批和派发流程。派发是将已审批的生产单正式下达到车间执行的关键环节，派发时需要同步生成工序任务和备料清单，以便车间进行生产准备。

### 1.2 功能目标

实现**一键派发**功能，在同一个事务中完成以下三步操作：

1. **派发生产单** — 更新生产单状态为"已派发"，同时写入设备、模具、班次等调度信息
2. **自动生成工序任务** — 根据产品匹配的工艺路线，自动拆解为工序任务
3. **自动生成备料单** — 根据产品匹配的BOM，展平物料树并计算需求量

### 1.3 业务流程图

```
┌─────────────┐     ┌─────────────┐     ┌──────────────┐
│  生产计划    │────>│  生产单管理  │────>│  提交审批    │
│  (Plan)     │     │  (创建/导入) │     │  (草稿→待审批)│
└─────────────┘     └─────────────┘     └──────┬───────┘
                                               │
                                               v
┌─────────────────────────────────────────────────────────────┐
│                     审批通过 (已审批)                         │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           v
┌─────────────────────────────────────────────────────────────┐
│                  一键派发 (dispatch-and-generate)             │
│                                                              │
│  ┌──────────────┐  ┌──────────────────┐  ┌───────────────┐  │
│  │ ① 派发生产单  │─>│ ② 生成工序任务    │─>│ ③ 生成备料单   │  │
│  │ 状态→已派发   │  │ 匹配工艺路线      │  │ 匹配BOM        │  │
│  │ 写入设备/模具 │  │ 拆解工序步骤      │  │ 展平物料树     │  │
│  │ 写入班次/日期 │  │ 写入工作中心      │  │ 计算需求量     │  │

│                                                              │
│  全部操作在同一数据库事务中，任何一步失败则全部回滚              │

                           v
            ┌──────────────────────────────┐
            │ 车间执行（备料、报工、完工）     │
            └──────────────────────────────┘
```

## 二、前置条件与业务规则

### 2.1 派发前置条件

| 条件 | 说明 | 校验层级 |
|------|------|----------|
| 审批状态 = "已审批" | 只有审批通过的生产单才能派发 | 前端 + 后端双重校验 |
| 计划状态 = "未开始" | 已派发或已完成的生产单不能重复派发 | 前端 + 后端双重校验 |
| 生产单存在 | 生产单编号必须有效 | 后端校验 |

### 2.2 工序任务生成规则

| 规则 | 说明 |
|------|------|
| 工艺路线匹配 | 根据生产单的 `item_number`（产品编号）匹配 `routing_header` 表，取最新的已启用且已审批的路线 |
| 去重保护 | 同一生产单 + 同一工序号不会重复生成（幂等性） |
| 编号格式 | `PT-YYYYMMDD-NNN`，如 `PT-20260323-001` |
| 初始状态 | `task_status = '未开始'`，`approval_status = '草稿'` |

### 2.3 备料单生成规则

| 规则 | 说明 |
|------|------|
| BOM匹配 | 根据生产单的 `item_number` 匹配 `bom_header` 表，取最新版本的已启用且已审批BOM |
| BOM展平 | 递归展开多级BOM，最大深度10层，防止循环引用 |
| 物料汇总 | 同一物料编号在多个BOM路径下出现时，累加需求量 |
| 需求量计算 | `需求量 = (计划数量 / BOM基数量) × 物料累计用量` |
| 去重保护 | 同一生产单已存在备料单时跳过 |
| 编号格式 | `MP-YYYYMMDD-NNN`，如 `MP-20260323-001` |
| 初始状态 | `preparation_status = '未领料'`，`approval_status = '草稿'` |

### 2.4 执行顺序依赖

工序任务**必须先于**备料单生成，原因是备料单明细中的 `work_center_number`（工作中心）字段来源于已生成的工序任务。

## 四、数据库操作详解

### 4.1 第一步：派发生产单

**操作表：** `production_order`

```sql
UPDATE production_order SET
  plan_status = N'已派发',
  equipment_number = :equipment_number,
  equipment_name = :equipment_name,
  mould_number = :mould_number,
  formed_part_specifications = :formed_part_specifications,
  formed_part_unit_consumption = :formed_part_unit_consumption,
  actual_cavity_count = :actual_cavity_count,
  actual_hole_count = :actual_hole_count,
  actual_daily_output = :actual_daily_output,
  production_date = :production_date,
  schedule_id = :schedule_id
WHERE production_order_number = :id
```

### 4.2 第二步：生成工序任务

**查询表：** `routing_header`、`routing_detail`  
**写入表：** `process_task`

**步骤：**

1. 根据产品编号匹配工艺路线主表

```sql
SELECT TOP 1 process_route_number, process_route_name
FROM routing_header
WHERE item_number = :item_number
  AND condition = N'启用'
  AND approval_status = N'已审批'
ORDER BY creation_date DESC
```

2. 读取路线明细（按工序号升序）

```sql
SELECT step_number, standard_process_number, standard_process_name,
  work_center_number, work_center_name, excess_reporting_ratio,
  ingredient_addition_method, process_material_input_number,
  process_material_input_quantity, process_material_input_unit,
  material_wastage_rate
FROM routing_detail
WHERE process_route_number = :prn
ORDER BY step_number
```

3. 逐条插入工序任务（含去重检查）

**字段映射：**

| process_task字段 | 数据来源 | 说明 |
|-----------------|----------|------|
| process_task_number | 自动生成 | PT-YYYYMMDD-NNN |
| production_order_number | 生产单 | 直接取值 |
| production_number | 生产单 | 直接取值 |
| process_route_number | routing_header | 工艺路线编号 |
| step_number | routing_detail | 工序序号 |
| item_number / item_name | 生产单 | 产品信息 |
| specifications / basic_unit | 生产单 | 规格/单位 |
| planned_quantity | 生产单 | 计划数量 |
| completed_quantity | 常量 | 初始值 0 |
| standard_process_number | routing_detail | 标准工序编号 |
| standard_process_name | routing_detail | 标准工序名称 |
| work_center_number | routing_detail | 工作中心编号 |
| work_center_name | routing_detail | 工作中心名称 |
| process_material_input_* | routing_detail | 物料投入信息 |
| material_wastage_rate | routing_detail | 损耗率 |
| task_status | 常量 | "未开始" |
| approval_status | 常量 | "草稿" |
| creation_date | 系统时间 | YYYY/MM/DD HH:mm |
| creation_man | 当前用户 | req.user.username |

### 4.3 第三步：生成备料单

**查询表：** `bom_header`、`bom_detail`、`process_task`  
**写入表：** `material_preparation`、`material_preparation_detail`

**步骤：**

1. 检查是否已有备料单（去重）
2. 匹配BOM主表

```sql
SELECT TOP 1 bom_number, bom_name, bom_version, base_quantity
FROM bom_header
WHERE item_number = :item_number
  AND [condition] = N'启用'
  AND approval_status = N'已审批'
ORDER BY bom_version DESC
```

3. 递归展平BOM（`flattenBomRecursive` 函数）

```
BOM主表 → BOM明细 → 子BOM检查 → 递归展开
                                    ↓
                            叶子节点物料列表
                            (含累计用量和BOM路径)
```

4. 按物料编号分组汇总
5. 从已生成的工序任务获取工作中心信息
6. 从BOM明细获取补充信息（关键物料、替代组、供应类型等）
7. 计算需求量

```
倍率 = 计划数量 / BOM基数量
需求量 = 倍率 × 物料累计用量（四舍五入到4位小数）
```

8. 插入备料单主表 + 逐条插入明细

**备料单主表字段映射：**

| 字段 | 来源 | 说明 |
|------|------|------|
| preparation_number | 自动生成 | MP-YYYYMMDD-NNN |
| production_order_number | 生产单 | 关联的生产单 |
| bom_number / bom_version | bom_header | BOM信息 |
| planned_quantity | 生产单 | 计划生产数量 |
| bom_base_quantity | bom_header | BOM基数量 |
| total_material_types | 计算 | 展平后物料种类数 |
| preparation_status | 常量 | "未领料" |
| approval_status | 常量 | "草稿" |

**备料单明细字段映射：**

| 字段 | 来源 | 说明 |
|------|------|------|
| line_number | 序号 | (index + 1) * 10 |
| material_number / material_name | 展平结果 | 叶子物料信息 |
| bom_standard_quantity | bom_detail | BOM标准用量 |
| bom_wastage_rate | bom_detail | 损耗率 |
| required_quantity | 计算 | 倍率 × 累计用量 |
| adjusted_quantity | 同上 | 初始值等于需求量 |
| issued_quantity | 常量 | 初始值 0 |
| step_number | bom_detail/展平 | 工序号 |
| work_center_number | process_task | 来自已生成的工序任务 |
| is_key_material | bom_detail | 是否关键物料 |
| supply_type | bom_detail | 供应类型 |
| default_warehouse | bom_detail | 默认仓库 |
| bom_path | 展平追踪 | BOM递归路径 |

## 五、前端交互设计

### 5.1 派发入口

**位置：** 生产单管理页面 `Order/List.vue`

**操作流程：**

1. 用户在生产单列表中勾选需要派发的记录
2. 点击"派发"按钮
3. 系统自动校验：
   - 所有选中记录的 `plan_status` 必须为"未开始"
   - 所有选中记录的 `approval_status` 必须为"已审批"
4. 打开派发对话框，展示可编辑的派发信息表格
5. 用户可以：
   - 批量设置设备、模具、生产日期、班次
   - 逐行修改每条记录的调度参数
6. 点击"确定派发"提交

### 5.2 派发确认

**确认对话框提示：**

> 将派发 N 条生产调度单，同时自动生成工序任务和备料单。

### 5.3 结果展示

派发完成后弹出**结果展示对话框**，包含：

- **总览统计区域：** 4个统计卡片
  - 成功派发 X 条（绿色）
  - 工序任务 X 条（蓝色）
  - 备料单 X 份（紫色）
  - 跳过 X 条（红色，仅在有跳过时显示）

- **详情折叠面板：** 每个生产单一个面板
  - 标题：派发状态标签 + 生产单号 + 工序/备料统计
  - 展开内容：工序任务和备料单的具体生成结果或跳过原因

- **错误告警区域：** 未能派发的生产单及其原因列表

### 5.4 前端校验逻辑

```typescript
// 检查计划状态
const invalidRecords = selectedRowKeys.value.filter(key => {
  const record = dataSource.value.find(d => d.production_order_number === key)
  return record && record.plan_status !== '未开始'
})
if (invalidRecords.length > 0) {
  message.warning('只能派发状态为"未开始"的记录，请重新选择')
  return
}

// 检查审批状态
const unapprovedRecords = selectedRowKeys.value.filter(key => {
  const record = dataSource.value.find(d => d.production_order_number === key)
  return record && record.approval_status !== '已审批'
})
if (unapprovedRecords.length > 0) {
  message.warning('只能派发审批状态为"已审批"的记录，请先完成审批')
  return
}
```

## 六、事务与异常处理

### 6.1 事务策略

所有操作在同一个数据库事务（`sequelize.transaction()`）中执行：

- 派发更新、工序任务插入、备料单插入共享同一事务
- 任何数据库异常导致事务回滚，所有更改撤销
- 单个生产单的工序/备料生成异常被捕获，不影响其他生产单

### 6.2 容错机制

| 场景 | 处理方式 |
|------|----------|
| 生产单不存在 | 跳过，记录错误信息 |
| 审批状态不符 | 跳过，记录错误信息 |
| 计划状态不符 | 跳过，记录错误信息 |
| 无匹配工艺路线 | 派发成功，工序任务标记为跳过 |
| 工艺路线无明细 | 派发成功，工序任务标记为跳过 |
| 工序任务已存在 | 自动跳过该工序（幂等） |
| 无匹配BOM | 派发成功，备料单标记为跳过 |
| BOM展平无物料 | 派发成功，备料单标记为跳过 |
| 备料单已存在 | 自动跳过（幂等） |
| 工序任务生成异常 | 捕获异常，记录原因，继续处理备料 |
| 备料单生成异常 | 捕获异常，记录原因 |
| 数据库事务异常 | 全部回滚 |
