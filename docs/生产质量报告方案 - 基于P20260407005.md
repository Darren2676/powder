## 二、生产质量报告设计方案

### 2.1 报告功能定位

基于现有数据结构（`production_order` → `process_task` → `work_report`），设计**生产质量报告**功能模块，实现：

1. **单个生产单的质量追溯** — 从生产单号出发，查看完整工序链的质量数据
2. **工序级质量分析** — 每道工序的合格率、不合格率、缺陷分布
3. **缺陷统计与趋势** — 按缺陷分类、缺陷类型、工序维度的统计
4. **综合质量评估** — 整体合格率、关键质量指标

### 2.2 报告数据模型

报告不需要新建数据库表，完全基于现有数据的**聚合查询**生成：

```
数据来源：
├── production_order        → 生产单基本信息（产品、数量、日期、设备、模具）
├── process_task            → 工序任务列表（工序名、工作中心、计划量、完成量）
├── work_report             → 报工记录（合格量、不合格量、缺陷信息、班组、操作员）
├── defect_class            → 缺陷分类字典
├── defect                  → 缺陷定义字典
└── defect_reason           → 缺陷原因字典
```

### 2.3 报告内容结构

#### 模块一：生产单概要卡片

## 三、技术实现方案

### 3.1 后端 API 设计

```
GET /api/quality-report/production/:production_order_number
    → 获取单个生产单的完整质量报告

GET /api/quality-report/summary
    → 质量汇总统计（支持按时间、产品、工序等筛选）
    参数：start_date, end_date, item_number, work_center_number

GET /api/quality-report/defect-analysis
    → 缺陷分析统计
    参数：start_date, end_date, item_number, defect_class_number

GET /api/quality-report/process-quality
    → 工序质量排名
    参数：start_date, end_date, standard_process_name
```

### 3.2 核心 SQL 查询

**单个生产单质量报告：**
```sql
-- 工序质量明细
SELECT
    pt.step_number,
    pt.standard_process_name,
    pt.work_center_name,
    pt.planned_quantity,
    pt.completed_quantity,
    wr.work_report_number,
    wr.qualified_quantity,
    wr.unqualified_quantity,
    wr.total_quantity,
    CASE WHEN wr.total_quantity > 0
         THEN CAST(wr.qualified_quantity * 100.0 / wr.total_quantity AS DECIMAL(5,2))
         ELSE 100 END AS pass_rate,
    wr.defect_class_name,
    wr.defect_name,
    wr.unqualified_reason,
    wr.report_date,
    wr.schedules_name,
    wr.group_name,
    wr.operator_name
FROM process_task pt
LEFT JOIN work_report wr ON wr.process_task_number = pt.process_task_number
WHERE pt.production_order_number = :production_order_number
ORDER BY pt.step_number
```

**质量汇总统计：**
```sql
-- 按产品汇总
SELECT
    po.item_number,
    po.item_name,
    po.specifications,
    COUNT(DISTINCT po.production_order_number) AS order_count,
    SUM(wr.qualified_quantity) AS total_qualified,
    SUM(wr.unqualified_quantity) AS total_unqualified,
    SUM(wr.total_quantity) AS total_reported,
    CASE WHEN SUM(wr.total_quantity) > 0
         THEN CAST(SUM(wr.qualified_quantity) * 100.0 / SUM(wr.total_quantity) AS DECIMAL(5,2))
         ELSE 100 END AS overall_pass_rate
FROM production_order po
INNER JOIN work_report wr ON wr.production_order_number = po.production_order_number
WHERE po.production_date BETWEEN :start_date AND :end_date
GROUP BY po.item_number, po.item_name, po.specifications
ORDER BY overall_pass_rate ASC
```

**缺陷TOP分析：**
```sql
SELECT
    wr.defect_class_name,
    wr.defect_name,
    wr.standard_process_name,
    COUNT(*) AS occurrence_count,
    SUM(wr.unqualified_quantity) AS total_defect_qty
FROM work_report wr
WHERE wr.unqualified_quantity > 0
    AND wr.report_date BETWEEN :start_date AND :end_date
GROUP BY wr.defect_class_name, wr.defect_name, wr.standard_process_name
ORDER BY total_defect_qty DESC
```

### 3.3 前端页面设计

```
成品库管理 / 质量管理
└── 生产质量报告
    ├── 搜索栏：生产单号搜索 + 产品筛选 + 日期范围 + 工序筛选
```

### 质量评估结论

| 评估项 | 结果 | 评定 |
|--------|------|------|
| 整体合格率 | 99.55% | ✅ 优良 |
| 计划达成率 | 100% (110/110) | ✅ 达标 |
| 工序零缺陷率 | 83.3% (5/6) | ⚠️ 关注 |
| 缺陷工序 | 包装(60) | 需改善 |
| 主要缺陷 | 外观/磨损 3PCS | 需分析根因 |

### 质量改善建议

1. **包装工序质量控制**
   - 包装工序出现3件磨损不合格品，需排查包装流程中的产品保护措施
   - 建议检查包装工位的操作规范，确认是否存在产品碰撞或摩擦的环节

2. **超额报工关注**
   - 包装工序报工总量111件（超出计划110件），表明有返工或补充生产情况
   - 建议关注超额报工的管理规则，确保数据准确性

3. **报工审批流程**
   - 当前所有6份报工单均处于"草稿"状态，未经正式审批
   - 建议建立报工审批流程，确保质量数据的可靠性
