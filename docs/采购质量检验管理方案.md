## 基于采购订单与收料检验方案的质量检验体系设计

---

## 一、现有数据基础

### 1.1 相关数据表概览

| 数据表 | 用途 | 现有数据量 |
|--------|------|-----------|
| `purchase_order` / `purchase_order_detail` | 采购订单及明细行 | 待业务使用 |
| `stock_in` / `stock_in_detail` | 来料入库及明细（含合格/不合格数） | 待业务使用 |
| `incoming_inspect_plan` | 收料检验方案（检验方法、抽检规则、检验员） | 125+ 条 |
| `incoming_inspect_spec` / `incoming_inspect_spec_item` | 来料检验规范（物料质量特性、上下限） | 50+ 条规范 |
| `quality_characteristic` | 质量特性字典（硬度、密度、拉伸强度等） | 47 条 |
| `defect_class` | 缺陷分类（外观/尺寸/性能/数量） | 4 类 |
| `defect` / `defect_reason` | 缺陷定义与缺陷原因 | 已配置 |

### 1.2 数据流关系

```
采购订单(purchase_order)
  └─→ 采购订单明细(purchase_order_detail)
        └─→ 来料入库(stock_in)
              ├─→ 入库明细(stock_in_detail) [含合格量/不合格量]
              │     ↕ 关联
              │   收料检验方案(incoming_inspect_plan) → 检验方法、抽检方式
              │   来料检验规范(incoming_inspect_spec) → 物料质量标准、上下限
              │
              └─→ 【新建】采购质量检验单(purchase_quality_inspection)
                    └─→ 检验明细(purchase_quality_inspection_detail)
                          ├─→ 质量特性检测值记录
                          ├─→ 缺陷记录
                          └─→ 检验结论
```

## 二、采购质量检验功能设计

### 2.1 功能定位

建立**采购质量检验**模块，实现从采购到库到检验全流程的质量管控：

1. **检验单自动生成** — 来料入库时，系统自动根据物料编号匹配收料检验方案和来料检验规范，生成检验单
2. **质量特性检测记录** — 逐项记录检测值（硬度、密度、拉伸强度等），系统自动判定合格/不合格
3. **缺陷记录** — 发现问题时记录缺陷分类、缺陷名称、缺陷原因
4. **检验结论** — 自动汇总检测结果，给出合格/不合格/让步接收结论
5. **检验统计报表** — 按供应商、物料、时间维度的来料质量分析

### 2.3 业务流程

```
采购订单 → 来料入库创建
                ↓
        系统自动匹配检验方案
        (incoming_inspect_plan + incoming_inspect_spec)
                ↓
        生成采购质量检验单 (purchase_quality_inspection)
        + 自动填充质量特性明细行 (purchase_quality_inspection_detail)
                ↓
        检验员执行检验
        ├─ 逐项填写实测值（计量型自动比对上下限判定合格）
        ├─ 记录缺陷信息（如有不合格项）
        └─ 确认检验结论
                ↓
        检验完成 → 更新入库单合格/不合格数量
                ↓
        合格品入库 → material_batch_inventory
```

### 2.4 检验单生成规则

| 场景 | 规则 |
|------|------|
| **触发时机** | 来料入库单创建时 / 手动创建 |
| **方案匹配** | 按物料编号(item_number)匹配 `incoming_inspect_plan.plan_name` |
| **规范匹配** | 按物料编号匹配 `incoming_inspect_spec.spec_name` |
| **抽样数量** | 根据 `incoming_inspect_plan.sampling_method` 和 `sampling_quantity` 计算 |
| **检验项目** | 从 `incoming_inspect_spec_item` 自动加载质量特性到明细行 |
| **自动判定** | 计量型数据：实测值在 [下限, 上限] 范围内为合格 |

### 2.5 检验结论判定

| 条件 | 结论 |
|------|------|
| 所有质量特性均合格，无缺陷 | **合格** |
| 存在不合格特性或缺陷 | **不合格** |
| 不合格但经审批可接收 | **让步接收** |

## 三、技术实现方案

### 3.1 后端 API 设计

```
POST /api/quality-report/purchase-inspection
    → 创建采购质量检验单（自动匹配检验方案和规范）
    参数：stock_in_number, stock_in_detail_id (或 item_number)

GET /api/quality-report/purchase-inspections
    → 检验单列表（支持按供应商、物料、状态、日期筛选）
    参数：page, limit, search, supplier_number, inspect_status, start_date, end_date

GET /api/quality-report/purchase-inspections/:inspection_number
    → 检验单详情（含检验特性明细行）

PUT /api/quality-report/purchase-inspections/:inspection_number
    → 更新检验单（填写实测值、缺陷信息、检验结论）

PUT /api/quality-report/purchase-inspections/:inspection_number/complete
    → 完成检验（更新状态，回写入库单合格数量）

GET /api/quality-report/purchase-inspection-summary
    → 采购质量统计（按供应商/物料汇总合格率）
```

### 3.2 核心 SQL 查询

**创建检验单时匹配检验方案：**
```sql
-- 匹配收料检验方案（按物料编号）
SELECT plan_name, inspector_id, inspector_name, inspect_department,
       inspect_method, sampling_method, sampling_quantity, decimal_handling
FROM incoming_inspect_plan
WHERE plan_name = :item_number
   OR applied_category LIKE '%' + :item_number + '%'

-- 匹配来料检验规范（按物料编号）
SELECT spec_name, defect_categories
FROM incoming_inspect_spec
WHERE spec_name = :item_number

-- 加载质量特性明细
SELECT id, spec_name, char_name, char_category, data_type,
       upper_limit, standard_value, lower_limit,
       inspect_requirement, sort_order
FROM incoming_inspect_spec_item
WHERE spec_name = :item_number
ORDER BY sort_order ASC
```

**检验单列表查询：**
```sql
SELECT * FROM (
  SELECT
    qi.inspection_number, qi.stock_in_number, qi.purchase_order_number,
    qi.supplier_number, qi.supplier_name,
    qi.item_number, qi.item_name, qi.specifications,
    qi.received_quantity, qi.sample_quantity,
    qi.qualified_quantity, qi.unqualified_quantity,
    qi.inspect_plan_name, qi.inspect_method,
    qi.inspector_name, qi.inspect_date,
    qi.inspect_result, qi.inspect_status,
    qi.batch_number, qi.defect_class_name, qi.defect_name,
    ROW_NUMBER() OVER (ORDER BY qi.creation_date DESC) AS _row_num
  FROM purchase_quality_inspection qi
  WHERE 1=1
    AND qi.inspect_status = :status     -- 可选
    AND qi.supplier_number = :supplier  -- 可选
    AND qi.inspect_date BETWEEN :start_date AND :end_date  -- 可选
) AS t WHERE t._row_num > :offset AND t._row_num <= :offsetEnd
```

**按供应商采购质量统计：**
```sql
SELECT
  qi.supplier_number,
  qi.supplier_name,
  COUNT(*) AS inspection_count,
  SUM(qi.received_quantity) AS total_received,
  SUM(qi.qualified_quantity) AS total_qualified,
  SUM(qi.unqualified_quantity) AS total_unqualified,
  CASE WHEN SUM(qi.received_quantity) > 0
       THEN CAST(SUM(qi.qualified_quantity) * 100.0 / SUM(qi.received_quantity) AS DECIMAL(5,2))
       ELSE 100 END AS pass_rate,
  SUM(CASE WHEN qi.inspect_result = N'不合格' THEN 1 ELSE 0 END) AS reject_count
FROM purchase_quality_inspection qi
WHERE qi.inspect_status = N'已完成'
  AND qi.inspect_date BETWEEN :start_date AND :end_date
GROUP BY qi.supplier_number, qi.supplier_name
ORDER BY pass_rate ASC
```

### 3.3 前端页面设计

```
质量管理
├── 生产单质量报告（已实现）
├── 按产品质量汇总（已实现）

    ├── 质量概览卡片区（4个指标卡）

    ├── 检验单列表（带状态标签：待检验/检验中/已完成）

        │   ├── 缺陷分类(下拉) | 缺陷名称(下拉) | 缺陷原因(下拉)
        │   └── 不合格数量 | 处理意见
        └── 检验结论区
            ├── 合格/不合格/让步接收（单选）
            └── 检验备注
```

## 四、与现有模块集成

### 4.1 与来料入库集成

| 集成点 | 说明 |
|--------|------|
| 入库创建 → 自动生成检验单 | 创建stock_in时，检查物料是否有检验方案，有则自动创建检验单 |
| 检验完成 → 回写入库单 | 检验完成后，将合格/不合格数量回写到stock_in_detail |
| 检验不合格 → 阻断入库 | 不合格物料标记为待处理，需让步接收后方可入库 |

### 4.2 与采购订单集成

| 集成点 | 说明 |
|--------|------|
| 供应商质量评估 | 汇总供应商的来料合格率，建立供应商质量档案 |
| 采购明细追溯 | 检验单关联采购订单号，支持从采购单追溯检验记录 |

### 4.3 与质量基础数据集成

| 基础数据 | 集成方式 |
|---------|---------|
| `incoming_inspect_plan` | 匹配检验方法、抽检方式、检验员 |
| `incoming_inspect_spec` + `_item` | 匹配质量特性项目、上下限标准 |
| `quality_characteristic` | 质量特性字典参考 |
| `defect_class` / `defect` / `defect_reason` | 检验缺陷记录时的选项来源 |
