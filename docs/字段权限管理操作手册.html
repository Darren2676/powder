一、权限体系概述

系统采用 4层RBAC权限体系，从粗到细依次为：

菜单 (menu) → 页面 (page) → 操作 (operation) → 字段 (field)
权限层级类型标识编码格式控制范围
菜单menusales-management侧边栏菜单是否可见
页面pagesales-prices页面路由是否可访问
操作operationsales-prices:view页面内按钮/功能是否可用
字段fieldsales-prices:field:tax_inclusive_price表格列/表单字段是否可见
核心理念：字段权限是最细粒度的控制。拥有页面查看权限但不拥有某字段权限的用户，将无法看到该字段对应的表格列和表单项。

二、字段权限数据结构

2.1 permission 表记录格式

字段值示例说明
permission_codesales-prices:field:tax_inclusive_price格式：{页面编码}:field:{字段名}
permission_name含税单价中文显示名，用于权限树展示
permission_typefield固定为 field
parent_id页面/菜单权限的ID挂在对应页面权限节点下
sort_order101排序号，100起为字段区间
status启用启用/停用

2.2 角色与权限关联

字段权限通过 role_permission 表关联到角色：

role ──1:N──> role_permission ──N:1──> permission (type=field)
角色 → role_permission → 字段权限 → 列可见性

三、管理操作流程

方式一：通过系统 UI 操作（推荐）

  1. 登录 admin 账号 → 进入 系统设置
  2. 角色管理 → 选择目标角色 → 点击 分配权限
  3. 在权限树中展开目标页面（如"销售价目表"），勾选/取消字段权限节点
  4. 点击保存，该角色用户重新登录后即生效
系统内置角色（admin、manager、staff）不可删除或禁用，但可以调整其权限配置。

方式二：通过权限管理 API 操作

适用于批量操作或自动化场景：

/* 1. 查看权限树，找到目标字段权限ID */
GET  /api/v1/permissions/tree

/* 2. 给角色分配字段权限（替换权限ID数组） */
PUT  /api/v1/roles/{roleId}/permissions
Body: { "permission_ids": [字段权限ID1, 字段权限ID2, ...] }

方式三：直接操作数据库（批量/迁移用）

/* 查看某页面的所有字段权限 */
SELECT id, permission_code, permission_name
FROM permission
WHERE permission_code LIKE 'sales-prices:field:%'
  AND permission_type = N'field';

/* 给角色添加字段权限 */
INSERT INTO role_permission (role_id, permission_id)
SELECT @roleId, id FROM permission
WHERE permission_code = 'sales-prices:field:tax_inclusive_price';

/* 移除角色的某字段权限 */
DELETE FROM role_permission
WHERE role_id = @roleId
  AND permission_id = (
    SELECT id FROM permission
    WHERE permission_code = 'sales-prices:field:tax_inclusive_price'
  );
注意：直接操作数据库时，需确保不会产生重复的 role_permission 记录。建议先查询是否已存在再插入。

四、新增字段权限步骤

当需要为新字段添加权限控制时，需要完成以下三步：

步骤1：数据库 — 插入字段权限记录

/* 先查询父级页面权限的ID */
SELECT id FROM permission
WHERE permission_code = 'sales-prices' AND permission_type IN (N'menu', N'page');

/* 插入字段权限 */
INSERT INTO permission (permission_name, permission_code, permission_type, parent_id, sort_order, status)
VALUES (N'含税单价', 'sales-prices:field:tax_inclusive_price', N'field', @页面权限ID, 101, N'启用');

步骤2：角色授权 — 分配给目标角色

/* 自动分配给 admin 角色（新权限建议自动分配） */
INSERT INTO role_permission (role_id, permission_id)
SELECT (SELECT id FROM role WHERE role_code = 'admin'), id
FROM permission
WHERE permission_code = 'sales-prices:field:tax_inclusive_price';

/* 同样分配给 manager 角色 */
INSERT INTO role_permission (role_id, permission_id)
SELECT (SELECT id FROM role WHERE role_code = 'manager'), id
FROM permission
WHERE permission_code = 'sales-prices:field:tax_inclusive_price';
提示：通过 API（POST /permissions）创建的权限会自动分配给 admin 角色，无需手动操作。

步骤3：前端接入 — 声明受控字段

在 Vue 页面组件中，通过 usePagePermission composable 接入：

/* 1. 导入 composable */
import { usePagePermission } from '@/composables/usePagePermission';

/* 2. 在 setup 中调用，获取 filterPermColumns */
const { filterPermColumns } = usePagePermission('sales-prices');

/* 3. 用 filterPermColumns 过滤列定义，注意 .value 解包 ComputedRef */
const filteredDataColumns = filterPermColumns(defaultDataColumns).value;

/* 4. 将 filteredDataColumns 传入 useColumnPreference */
const { dataColumns } = useColumnPreference('sales-prices', filteredDataColumns);
重要：filterPermColumns() 返回的是 ComputedRef，必须加 .value 才能得到实际数组。漏掉 .value 会导致运行时报错 "dataCols is not iterable"。

六、权限生效机制

6.1 权限加载流程

用户登录 → /permissions/mine API → permission Store → localStorage 持久化 → 页面渲染时过滤列

6.2 角色权限规则

角色字段权限行为
admin自动拥有所有字段权限，不受限制（isAdmin = true 时直接放行）
manager默认拥有所有字段权限（迁移脚本自动分配）
staff默认无价格字段权限
自定义角色仅显示 role_permission 关联的字段；未授权的列在 filterColumns() 时被过滤掉

6.3 生效时机

  • 权限变更后，用户需要重新登录才能生效
  • 登录时权限数据从 /permissions/mine 接口加载，并持久化到 localStorage
  • 页面刷新时从 localStorage 恢复权限，无需再次请求接口

6.4 路由守卫机制

非 admin 用户访问页面时，路由守卫检查：

if (!permStore.hasPermission(permCode) && !permStore.hasMenuKey(permCode)) {
  // 无菜单级或页面级权限 → 重定向到 Dashboard
  next({ name: 'Dashboard' });
}
要让受限用户能访问页面，角色需要同时拥有菜单/页面级权限（如 sales-prices）和查看操作权限（如 sales-prices:view）。仅有 sales-prices:view 而无菜单级权限会被路由守卫拦截。

七、故障排查

现象可能原因解决方法
登录后看不到价格列 角色未分配该字段权限 在角色管理中勾选对应的字段权限节点
页面空白或报错 "dataCols is not iterable" filterPermColumns() 返回 ComputedRef，漏了 .value 检查 List.vue 中是否写了 .value：filterPermColumns(defaultDataColumns).value
受限用户无法访问页面（被重定向到首页） 缺少菜单/页面级权限，路由守卫拦截 确保角色同时拥有菜单权限（如 sales-prices）和查看权限（如 sales-prices:view）
权限变更后未生效 用户未重新登录，localStorage 中仍是旧权限 退出登录后重新登录，或清除浏览器 localStorage
admin 用户也看不到列 isAdmin 标志未正确设置 检查用户角色是否包含 admin；检查 /permissions/mine 返回的 isAdmin 值
新增字段权限后角色看不到 权限未分配给角色 在角色管理中分配，或通过 SQL 插入 role_permission 记录
