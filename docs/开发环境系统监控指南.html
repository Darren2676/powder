2. 健康检查接口

2.1 接口定义

项目说明
路径GET /api/v1/health
认证无需认证（公开端点）
成功状态码200
降级状态码503（数据库异常）

2.2 返回结构

{ "status": "healthy", // healthy | degraded "timestamp": "2026-05-26T15:00:13.000Z", "uptime": "2h 35m", // 服务运行时长 "database": "ok", // ok | error "memory": { "rss": "156MB", // 进程驻留内存 "heapUsed": "89MB", // V8堆已用 "heapTotal": "128MB" // V8堆总量 } }

2.3 实现逻辑

// server/src/app.ts app.get(`${API_PREFIX}/health`, async (_req, res) => { const uptime = process.uptime(); const memUsage = process.memoryUsage(); let dbStatus = 'ok'; try { await sequelize.authenticate(); // 测试数据库连接 } catch { dbStatus = 'error'; } res.status(dbStatus === 'ok' ? 200 : 503).json({ status: dbStatus === 'ok' ? 'healthy' : 'degraded', timestamp: new Date().toISOString(), uptime: `${Math.floor(uptime / 3600)}h ${Math.floor((uptime % 3600) / 60)}m`, database: dbStatus, memory: { rss: `${Math.round(memUsage.rss / 1024 / 1024)}MB`, heapUsed: `${Math.round(memUsage.heapUsed / 1024 / 1024)}MB`, heapTotal: `${Math.round(memUsage.heapTotal / 1024 / 1024)}MB` } }); });

2.4 字段说明

字段类型含义异常阈值
statusstring服务整体状态degraded 表示数据库异常
uptimestring进程运行时长频繁重置需排查
databasestring数据库连通性error 表示连接失败
memory.rssstring进程驻留内存超过 800MB 需关注
memory.heapUsedstringV8堆已用内存接近 heapTotal 需关注

4. 日志系统

4.1 Pino 结构化日志

系统采用 Pino 作为日志框架，提供结构化 JSON 输出、日志级别控制、请求追踪和模块标识。

4.1.1 配置文件

// server/src/config/logger.ts const logger = pino({ level: process.env.LOG_LEVEL || (isDev ? 'debug' : 'info'), transport: isDev ? { target: 'pino-pretty', options: { colorize: true, translateTime: 'SYS:yyyy-mm-dd HH:MM:ss.l' } } : undefined, base: { service: 'seals-mes', env: process.env.NODE_ENV || 'development' }, timestamp: pino.stdTimeFunctions.isoTime, });

4.3 HTTP 请求日志

每个 HTTP 请求自动记录完整生命周期：

// 请求开始 [INFO] http: GET /api/v1/return-orders { requestId: "uuid-xxx", method: "GET", path: "/api/v1/return-orders", userId: 1 } // 请求完成（含耗时） [INFO] http: GET /api/v1/return-orders 200 45ms { requestId: "uuid-xxx", statusCode: 200, duration: 45 } // 4xx 警告 [WARN] http: POST /api/v1/return-orders/RT-xxx/cancel 400 12ms { statusCode: 400, duration: 12 } // 5xx 错误 [ERROR] http: GET /api/v1/return-orders 500 2300ms { statusCode: 500, duration: 2300 }
性能基线：正常 API 响应 < 200ms；200ms~1s 需关注慢查询；> 1s 通常为数据库性能问题。

4.4 日志输出格式

5. SSE 实时推送监控

5.1 架构说明

系统内置 SSE（Server-Sent Events）推送服务，用于移动端实时接收通知。每个用户连接维护一个 Response 对象，心跳保活每30秒发送注释行，连接断开时自动清理。

5.2 事件类型

事件类型说明触发场景
notification系统通知消息推送
approval审批通知审批流状态变更
task_update任务更新生产任务状态变更
system系统消息全局广播

5.3 心跳机制

// 每 30 秒发送心跳 :heartbeat // SSE 注释行，客户端自动忽略 // 客户端通过心跳判断连接存活 // 超过 60 秒未收到心跳或数据 → 判定连接断开 → 自动重连

// client/vite.config.ts server: { proxy: { '/api/v1': { target: 'http://localhost:3000', // 后端地址 changeOrigin: true }, '/uploads': { target: 'http://localhost:3000', changeOrigin: true } } }
重要：Vite 仅代理 /api/v1 和 /uploads 前缀的请求。如果 API 路径写错（如 /api/ 而非 /api/v1/），请求会被 SPA fallback 拦截，返回前端 index.html 而非 API 响应。

9. 常见故障排查

#症状可能原因排查步骤
1 API 请求返回管理驾驶舱页面 Vite 代理未匹配 API 路径 ① 检查 URL 是否以 /api/v1/ 开头
② 检查 vite.config.ts 代理规则
2 401 未提供认证令牌 新标签页不携带 Authorization header ① 检查打印URL是否携带 ?token=xxx
② 检查 auth.middleware.ts 是否支持 query token
3 端口 3000 被占用 旧进程未释放 ① netstat -ano | findstr :3000
② Stop-Process -Id <PID> -Force
③ 重新启动
4 数据库连接失败 SQL Server 未启动或 .env 配置错误 ① 检查 SQL Server 服务状态
② 验证 .env 中 DB_HOST/DB_PORT/DB_NAME
③ Invoke-RestMethod /api/v1/health 查看 database 字段

② 检查 SQL Server 活动监视器

6 前端修改不生效 Vite HMR 未触发 / 浏览器缓存 ① 强制刷新 (Ctrl+Shift+R)
② 检查终端 Vite 是否检测到文件变更
7 后端修改不生效 nodemon 未检测到变更 ① 检查终端 nodemon 是否重启
② 手动输入 rs 触发重启

10.2 日志使用规范

推荐做法：
  • 业务关键操作使用 log.info()（入库、出库、审批、确认等）
  • 可恢复异常使用 log.warn()（入库失败但不影响确认）
  • 不可恢复错误使用 log.error()（数据库异常、事务回滚）
  • 调试信息使用 log.debug()（变量值、中间计算结果）
  • 每条日志携带上下文对象：log.info({ orderNo }, '订单创建成功')
避免做法：
  • 禁止使用 console.log()，统一使用 Pino 日志器
  • 禁止在日志中输出敏感信息（密码、Token、个人信息）
  • 禁止在生产环境使用 LOG_LEVEL=debug
