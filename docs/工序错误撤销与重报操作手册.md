# 工序错误撤销与重报操作手册

> **适用场景**：生产执行过程中，某道工序报工数据有误（合格数/不合格数填错、报错工序等），需要撤销已报工记录并重新报入正确数据。

---

## 一、整体流程概览

```
发现工序N报工错误
      │
      ├─ 生产单已入库？
      │   ├─ 是 → 【步骤A】入库撤回 → 回到未入库状态
      │   └─ 否 → 继续下一步
      │
      ├─ 【步骤B】逆向删除报工单
      │   ├─ 从末道工序往错误工序方向，逐个删除报工记录
      │   └─ 若有检验单 → 同步删除/回退检验单
      │
      ├─ 【步骤C】重新报工
      │   └─ 使用修正后的合格数/不合格数重新提交报工
      │
      └─ 【步骤D】重新检验（如有）
            └─ 填写检验结果 → 完成检验
```

---

## 二、前置条件

| 条件 | 说明 |
|------|------|
| 报工单状态为"草稿" | 已提交或已审批的报工单不允许直接删除，需要先撤回审批 |
| 拥有报工单删除权限 | 系统需配置对应的角色权限 |
| 确认错误工序位置 | 明确是哪道工序、什么数据填错了 |

---

## 三、API 接口速查

| 操作 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 删除报工单 | `DELETE` | `/api/v1/work-reports/:work_report_number` | 仅允许删除"草稿"状态 |
| 快速报工 | `POST` | `/api/v1/work-reports/quick` | 提交修正后的报工数据 |
| 入库撤回 | `POST` | `/api/v1/finished-goods/inbound-orders/:inbound_order_number/withdraw` | 撤回成品入库单 |
| 查询检验单 | `GET` | `/api/v1/quality/production-inspections/by-order/:orderNo` | 查生产单的所有检验单 |
| 完成检验 | `PUT` | `/api/v1/quality/production-inspections/:id/complete` | 完成检验判定 |

---

## 四、详细操作步骤

### 步骤A：入库撤回（如生产单已入库）

**触发条件**：生产单已执行成品入库操作（`plan_status` = "已完成"，`inbound_status` = "全部入库"或"部分入库"）

**操作**：
1. 在"成品入库单列表"找到对应生产单的入库单号
2. 执行入库撤回操作
3. 验证：`inbound_status` 变为空或 null，生产单回到可重新入库状态

> ⚠️ **注意**：入库撤回后，成品批次库存和汇总库存都会回退，倒冲扣减的物料也会恢复。

---

### 步骤B：逆向删除报工单

**核心原则**：**从末道工序往错误工序方向，逐道删除**。因为后道工序的报工依赖于前道工序的完成数据（跨工序数量验证），必须先删除后道再删前道。

**操作流程**：

1. **定位错误工序**：确认报错的工序编号（`process_task_number`）
2. **查询该生产单所有工序的报工记录**：按 `creation_date` 倒序排列，从末道工序开始
3. **逐道删除**：

```
for 工序 = 末道 → 错误工序:
    查找本工序的所有"草稿"报工单
    DELETE /api/v1/work-reports/:work_report_number
    验证：工序 completed_quantity 减少，task_status 可能回退
```

**系统自动回退内容**：

| 回退项 | 说明 |
|--------|------|
| `work_report` 记录 | 物理删除报工单行 |
| `process_task.completed_quantity` | 扣减已报工数量（`completed_quantity - 合格数量`） |
| `process_task.task_status` | 可能回退："已完成"→"进行中"、"进行中"→"未开始" |
| `production_order.plan_status` | 可能回退："生产中"→"已备料"（如果所有工序都删了） |
| 线边仓流水冲销 | 对应 `lineside_inventory_transaction` 写入冲销记录 |
| 综合合格率重算 | `production_order.yield_rate` 重新计算 |

4. **处理关联检验单**（如有）：

| 检验状态 | 处理方式 |
|----------|----------|
| 检验已完成 | 需要手动删除或回退检验单（`production_inspection`） |
| 检验未开始 | 自动随报工单删除而失效 |
| 已创建 NC 单 | 需要先处理 NC 单（让步接收/报废/返修需回退或关闭） |

> ⚠️ **删除限制**：只有 `approval_status = '草稿'` 的报工单才能删除。如果已提交审批，需先在系统中撤回审批。

---

### 步骤C：重新报工

删除错误记录后，使用修正后的数据重新报工。

**接口**：`POST /api/v1/work-reports/quick`

**请求体**：
```json
{
  "process_task_number": "工序任务编号",
  "qualified_quantity": 修正后的合格数量,
  "unqualified_quantity": 修正后的不合格数量,
  "report_date": "2026-05-15",
  "remark": "修正重报 — 原报工单XX数据有误"
}
```

**报工前系统自动校验**：

| 校验项 | 规则 |
|--------|------|
| 工序审批状态 | 必须为"已审批" |
| 工序任务状态 | 不能为"已完成"或"已关闭" |
| 物料门控 | 首道：必须已备料或倒冲；非首道：该工序物料已领料 |
| 委外阻断 | 上道工序为委外且未完成时拒绝 |
| 超额报工 | (合格+不合格) ≤ 最大可报工量 |
| 跨工序数量 | 中间工序合格数 ≤ 前道完成数 - 本道已完成数 |
| 检验门控 | 上道工序检验状态必须为"检验合格"/"无需检"/"已处理" |

---

### 步骤D：重新检验（如有）

如果该工序配置了检验类型（专检/自检），重新报工后会触发检验单自动创建。

**操作**：
1. 查询该工序的检验单 → `GET /api/v1/quality/production-inspections/by-order/:orderNo`
2. 更新检验结果 → `PUT /api/v1/quality/production-inspections/:id`
3. 完成检验 → `PUT /api/v1/quality/production-inspections/:id/complete`

---

## 五、常见报错与处理

| 错误提示 | 原因 | 解决方法 |
|----------|------|----------|
| "已提交或已审批的报工单不允许删除" | 报工单已审批 | 先在审批模块撤回审批，再删除 |
| "首道工序报工需先完成首道工序物料领料" | 删除后 plan_status 回退到"已派发" | 先确保首道物料已领料，或将 plan_status 手动更新为"已备料" |
| "上道工序检验状态为'待检验'" | 删除了后道报工但上道检验未完成 | 先完成上道工序的检验 |
| "合格数量超过可报数量" | 跨工序数量约束不满足 | 确保前道工序已完成足够数量 |
| "报工单不存在" (404) | 报工单号错误或已被删除 | 检查报工单号是否正确 |
| "入库撤回失败" | 入库单已关联后续操作（如装箱/出货） | 需先取消后续关联操作 |

## 六、完整示例

**场景**：生产单 `P20260515001` 有 5 道工序（硫化→修边→外观全检→抽检→包装），第3道"外观全检"合格数报错为 3000，实际应为 2000。

**操作步骤**：

```
1. 确认未入库 → 跳过步骤A

2. 逆向删除：
   ├─ 删除第5道(包装)报工单 WR-20260515-005  → task_status 回退
   ├─ 删除第4道(抽检)报工单 WR-20260515-004  → task_status 回退
   └─ 删除第3道(外观全检)报工单 WR-20260515-003 → completed_quantity 扣减

3. 修正数据重新报工：
   ├─ 重新报第3道：qualified=2000, unqualified=0
   ├─ 完成第3道检验（专检）
   ├─ 重新报第4道：qualified=2000, unqualified=0
   ├─ 完成第4道检验（自检）
   ├─ 重新报第5道：qualified=2000, unqualified=0
   └─ 完成第5道检验（专检）

4. 生产单 plan_status → 已完成 → 重新入库
```

---

## 七、注意事项

1. **顺序不可逆**：从末道→错误工序的删除顺序是强制约束，不可跳过中间工序直接删除错误工序
2. **检验单联动**：删除报工单不会自动删除检验单，需要另行处理
3. **NC 单处理**：如果错误工序已创建不合格品单（NC）且已处理（让步/报废/返修），需先将 NC 处理回退
4. **数据一致性**：每次删除后建议验证 `process_task.completed_quantity` 和 `production_order.plan_status` 是否符合预期
5. **审计追溯**：建议在报工单 `remark` 字段记录"原报工单 XX 因数据错误撤销重报"，便于后续审计
