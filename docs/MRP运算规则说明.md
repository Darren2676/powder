# MRP 运算规则说明

## 一、概述

MRP（Material Requirements Planning，物料需求计划）是本系统的核心运算模块，用于根据已审批的生产计划，通过 BOM 逐层分解，自动计算各层级物料的净需求，并生成生产单和采购申请。

系统采用**广度优先分层分解算法**，最多支持 10 层 BOM 深度，所有数量计算保留 4 位小数精度（DECIMAL(18,4)）。

---

## 二、运算前提条件

MRP 运算基于**已审批的生产计划**，必须同时满足以下条件：

| 条件字段 | 要求值 | 说明 |
|---------|--------|------|
| `approval_status` | 已审批 | 计划需经审批流程通过 |
| `plan_status` | 待加入任务 | 计划处于可执行状态 |
| `mrp_status` | NULL | 未被 MRP 分解过 |

用户在前端界面勾选符合条件的生产计划后，点击"运行MRP"触发运算。

---

## 三、核心算法流程

### 3.1 整体流程

```
生产计划（已审批）
    │
    ▼
Step 1: 创建 MRP 运行记录
    │
    ▼
Step 2: 成品层（Level 0）— 直接展开制造 BOM
    │
    ▼
Step 3: 子件层（Level 1+）— 需求归集 → 净需求计算 → 行动决策 → 递归展开
    │
    ▼
Step 4: 写入运算结果（mrp_run_detail 表）
    │
    ▼
Step 5: 用户审查决策（双源物料分配数量）
    │
    ▼
Step 6: 执行 MRP — 生成生产单 + 采购申请
```

### 3.2 成品层处理（Level 0）

成品层不进行净需求计算（需求已由 MPS 主计划确定），直接展开制造 BOM：

1. 查询成品对应的**制造 BOM**（`mfg_bom_header`，需状态为"启用"且"已审批"）
2. 查询成品的**提前期**（`item_master.lead_time_days`）
3. 计算子件需求量：

```
子件需求量 = 成品计划数量 × (BOM 子件实际用量 / BOM 基准数量)
```

4. 子件的完成日期 = 成品完成日期 - 成品提前期天数
5. 所有子件加入队列，进入 Level 1 处理

### 3.3 子件层处理（Level 1+）

#### 3.3.1 需求归集

同一物料可能被多个父件引用，系统自动归集：

- **数量累加**：同一物料的毛需求合并求和
- **日期取早**：多个来源取最早的完成日期
- **来源追溯**：记录所有来源计划编号和父物料编号

#### 3.3.2 净需求计算

**核心公式：**

```
净需求 = MAX(0, 毛需求 - 可用供应 + 安全库存)

可用供应 = 现有库存 + 在制品数量 + 采购订单在途 + 采购申请待执行
```

各数据项来源如下：

| 数据项 | 来源表 | 计算方式 |
|-------|--------|---------|
| 现有库存 | `material_inventory` | `SUM(quantity)`，按物料编号汇总 |
| 安全库存 | `material_inventory` 或 `item_master` | 优先取 `material_inventory.safety_stock_quantity`；若为 0 且 `item_master.safety_stock_enabled = 'Y'`，则取 `item_master.safety_stock_qty` |
| 在制品数量 | `production_order` | `SUM(planned_quantity)`，条件：`approval_status = '已审批'` 且 `plan_status` 不在 ('已完成', '已关闭') |
| 采购订单在途 | `purchase_order_detail` + `purchase_order` | `SUM(order_quantity - received_quantity)`，条件：主表 `approval_status = '已审批'` |
| 采购申请待执行 | `purchase_req_detail` + `purchase_req` | `SUM(request_quantity - ordered_quantity)`，条件：主表 `approval_status = '已审批'` 且明细 `status = '未执行'` |

**计算示例：**

| 项目 | 值 |
|------|-----|
| 毛需求 | 1000 |
| 现有库存 | 200 |
| 在制品 | 300 |
| 采购在途 | 100 |
| 采购申请待执行 | 50 |
| 安全库存 | 100 |
| **可用供应** | 200 + 300 + 100 + 50 = **650** |
| **净需求** | MAX(0, 1000 - 650 + 100) = **450** |

#### 3.3.3 提前期处理

- **提前期来源**：`item_master.lead_time_days`
- **开始日期计算**：`开始日期 = 完成日期 - 提前期天数`
- **层级传递**：子件的完成日期 = 父件的开始日期（逐层向前递推）

示例（3层 BOM）：

```
成品 A：完成日期 4/30，提前期 5天 → 开始日期 4/25
  └─ 子件 B：完成日期 4/25，提前期 3天 → 开始日期 4/22
       └─ 原材料 C：完成日期 4/22，提前期 7天 → 开始日期 4/15
```

#### 3.3.4 行动类型决策

根据物料的**业务范围**（`item_master.business_scope`）和是否有制造 BOM 决定采取行动：

| 业务范围（business_scope） | 有无制造 BOM | 行动类型 | 说明 |
|--------------------------|-------------|---------|------|
| 含"生产"且含"采购" | 任意 | 生产+采购 | 双源物料，由用户手动分配生产和采购数量 |
| 仅含"生产" | 任意 | 生产 | 全部通过生产满足 |
| 仅含"采购" | 任意 | 采购 | 全部通过采购满足 |
| 空 / NULL | 有 BOM | 生产 | 有配方默认生产 |
| 空 / NULL | 无 BOM | 采购 | 无配方默认采购 |

**重要规则：行动类型为"采购"的物料，不展开其 BOM 子件。**

#### 3.3.5 BOM 子件展开条件

仅在同时满足以下条件时才展开 BOM 子件：

1. 该物料有启用且已审批的制造 BOM
2. 净需求 > 0
3. 行动类型为"生产"或"生产+采购"

## 四、运算结果

### 4.1 结果数据结构

每个物料生成一条 `mrp_run_detail` 记录，包含以下信息：

| 字段分组 | 包含字段 |
|---------|---------|
| **物料信息** | 物料编号、名称、规格、单位、类型、业务范围 |
| **BOM 信息** | BOM 层级、父物料编号、制造 BOM 编号、BOM 路径 |
| **需求与库存** | 毛需求、现有库存、在制品、采购在途、采购申请待执行、安全库存、净需求 |
| **计划日期** | 计划开始日期、计划完成日期、提前期天数 |
| **决策结果** | 行动类型、结果状态、生产数量、采购数量、生成的订单编号 |

### 4.2 结果状态

| 状态 | 说明 |
|------|------|
| 待确认 | 初始状态，等待用户审查 |
| 已确认 | 用户确认并执行后 |
| 已跳过 | 双源物料选择纯采购时，其子件自动跳过 |

---

## 五、MRP 执行（生成订单）

用户审查运算结果并决策后，执行 MRP 将生成：

### 5.1 生产单

- 写入 `production_order` 表
- 来源于行动类型为"生产"或"生产+采购"的物料
- 初始状态：`plan_status = '未开始'`，`approval_status = '草稿'`

### 5.2 采购申请

- 写入 `purchase_req` + `purchase_req_detail` 表
- 来源于行动类型为"采购"或"生产+采购"的物料
- 采购申请关联 MRP 运行编号（`source_number`）
- 后续可由采购员转化为采购订单

### 5.3 双源物料特殊处理

当双源物料（行动类型为"生产+采购"）用户选择**纯采购**（生产数量 = 0）时：
- 该物料的所有 BOM 子项自动标记为"已跳过"
- 子项的生产数量和采购数量均设为 0
- 避免产生不必要的子件需求

### 5.4 原始计划处理

MRP 执行完成后，原始生产计划的状态更新：
- `plan_status` → '已加入任务'
- `mrp_status` → '已分解'

## 六、MRP 运行生命周期

```
┌─────────┐    运行MRP    ┌─────────┐   用户确认   ┌─────────┐
│  选择计划 │ ──────────▶ │  已计算   │ ──────────▶ │  已确认   │
└─────────┘              └─────────┘              └─────────┘
                              │                       │
                              │ 取消                   │ 生成订单
                              ▼                       ▼
                         ┌─────────┐           ┌──────────────┐
                         │  已取消   │           │ 生产单+采购申请 │
                         └─────────┘           └──────────────┘
                              │
                              │ 删除
                              ▼
                         ┌─────────┐
                         │  已删除   │
                         └─────────┘
```

- **已计算**：MRP 运算完成，等待用户审查
- **已确认**：用户已确认并执行，订单已生成
- **已取消**：用户取消本次运算（仅"已计算"状态可取消）
- 仅"已取消"状态的运行记录可删除

## 七、API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/mrp/plans-for-mrp` | 获取可 MRP 的生产计划列表 |
| POST | `/api/mrp/run` | 运行 MRP 计算 |
| GET | `/api/mrp` | 查询 MRP 运行历史（分页） |
| GET | `/api/mrp/:mrp_run_number` | 查询 MRP 运行详情 |
| POST | `/api/mrp/execute` | 执行 MRP（生成生产单和采购申请） |
| POST | `/api/mrp/:mrp_run_number/cancel` | 取消 MRP 运行 |
| DELETE | `/api/mrp/:mrp_run_number` | 删除已取消的 MRP 运行 |

## 八、与其他模块的关系

```
销售订单 + 销售预测
        │
        ▼
   MPS 主计划（计算成品净需求）
        │
        ▼
   生产计划（已审批）
        │
        ▼
   MRP 运算（BOM 分解）
        │
        ├──▶ 生产单（production_order）──▶ 工序任务 ──▶ 报工 ──▶ 完工入库
        │
        └──▶ 采购申请（purchase_req）──▶ 采购订单 ──▶ 来料入库
```

---

## 九、关键数据库表

| 表名 | 用途 |
|------|------|
| `mrp_run` | MRP 运行主表（编号、状态、统计） |
| `mrp_run_plan` | MRP 关联的生产计划 |
| `mrp_run_detail` | MRP 计算详情（每个物料一行） |
| `mfg_bom_header` / `mfg_bom_detail` | 制造 BOM（分解依据） |
| `item_master` | 物料主数据（提前期、安全库存、业务范围） |
| `material_inventory` | 原材料库存（现有量、安全库存） |
| `production_order` | 生产单（在制品来源） |
| `purchase_order_detail` | 采购订单明细（在途来源） |
| `purchase_req_detail` | 采购申请明细（待执行来源） |

---

## 十、精度规则

- 所有数量字段使用 `DECIMAL(18,4)` 存储
- 运算过程中使用 `Math.round(value * 10000) / 10000` 保留 4 位小数
- 防止 JavaScript 浮点数精度导致的计算偏差
