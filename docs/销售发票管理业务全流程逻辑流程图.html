销售发票管理业务全流程逻辑流程图

睿信橡胶密封件MES系统 | 从销售发货、客户对账、录入发票、关联发货明细行、双向查询、到错误修正（编辑/撤消）及状态联动回退的全链路业务流程
文档说明：本文档完整展示销售发票管理业务的6个阶段：
阶段1 销售发货完成：销售订单审批 → 发货申请 → 创建发货单 → 仓库出库确认 → 发货完成
阶段2 客户对账：与客户核对发货数量/金额 → 确认开票需求 → 获取国家税务系统发票信息
阶段3 录入发票与关联：创建发票（草稿）→ 选择发货明细行 → 填写开票数量（支持部分开票）→ 保存
阶段4 审批发票：审批 → 联动更新发货明细行/销售订单明细行的开票状态（未开票/部分开票/已开票）
阶段5 双向查询：发票→查看关联发货明细行；发货明细行/销售订单明细行→查看关联发票
阶段6 错误修正：编辑发票（已审批自动撤消后编辑）、撤消审批、删除 → 联动回退开票状态和数量
涵盖状态流转、数据变更矩阵、关键业务规则及各环节的数据实体关系。

对账规则：
① 客户对账是业务环节，不在系统中流转，但决定开票数量
② 一张税务发票可对应多个发货单的多行明细（合并开票）
③ 一个发货明细行也可拆分到多张发票（分批开票）
④ 开票数量不能超过发货数量减去已开票数量：invoice_quantity ≤ ship_quantity - 已审批发票的SUM(invoice_quantity)

开票状态计算公式：
① 发货明细行：invoiced_qty = SUM(sil.invoice_quantity) FROM sales_invoice_line sil INNER JOIN sales_invoice si WHERE si.approval_status = '已审批' AND sil.shipping_detail_id = :id
② 销售订单明细行：invoiced_qty = SUM(sil.invoice_quantity) FROM sales_invoice_line sil INNER JOIN sales_invoice si WHERE si.approval_status = '已审批' AND sil.sales_detail_id = :id
③ 状态判定：invoiced_qty = 0 → 未开票；0 < invoiced_qty < order_quantity → 部分开票；invoiced_qty ≥ order_quantity → 已开票
④ 仅统计已审批发票：草稿发票的明细行不参与开票数量计算

④ 已审批发票禁止删除：必须先撤消为草稿，再删除
