销售人员数据范围权限操作手册

一、功能概述

销售人员数据范围权限（Data Scope）是一种基于角色的行级数据隔离机制。当用户的角色为 销售人员 时，系统自动过滤数据，使其仅能查看自己负责的客户及其关联的销售订单、发货申请和发货单信息。管理员、经理和普通员工不受此限制。

1.1 角色与数据范围对照

角色标签色数据范围
管理员红色全部数据，无限制
经理橙色全部数据，无限制
员工蓝色全部数据，无限制
销售人员绿色仅自己负责的客户及关联数据

1.2 数据过滤范围

模块过滤方式说明
客户管理head_of_sales_id = 当前用户ID仅显示当前用户为"销售负责人"的客户
销售订单head_of_sales_id = 当前用户ID仅显示当前用户负责客户的订单（含仪表板统计）
发货申请通过 customer 子查询仅显示当前用户负责客户的发货申请
发货单通过 customer 子查询仅显示当前用户负责客户的发货单
待发货列表通过订单 head_of_sales_id仅显示当前用户负责客户的待发货明细
数据范围过滤仅作用于"查看/列表/导出"操作，不影响创建和编辑。销售人员仍可为任何客户创建订单，但列表中只能看到自己负责的客户数据。

二、配置步骤

1
在用户管理中，将销售人员的角色改为 "销售人员"
↓
2
在客户管理中，为每个客户选择对应的 "销售负责人"
↓
3
销售人员登录后，系统自动过滤数据，仅显示其负责的客户及关联订单/发货信息

2.1 步骤一：设置用户角色

  1. 以管理员身份登录系统
  2. 进入 系统管理 → 用户管理
  3. 找到目标销售人员，点击 "编辑"
  4. 将角色从"员工"改为 "销售人员"
  5. 点击 "保存"
角色筛选下拉中已新增"销售人员"选项，可快速筛选所有 sales 角色用户。

2.2 步骤二：为客户指定销售负责人

  1. 进入 主数据 → 客户管理
  2. 点击客户的 "编辑" 按钮
  3. 在"销售负责人"字段，从下拉列表中选择对应的销售人员（支持模糊搜索姓名）
  4. 点击 "保存"
  • 销售负责人字段已从手动输入改为下拉选择用户，选择后系统自动关联用户ID，确保数据范围过滤准确。
  • 一个客户只能指定一个销售负责人。
  • 已有客户的历史数据已通过迁移脚本自动回填（根据原"销售负责人"文本匹配用户姓名）。

2.3 步骤三：验证数据范围

  1. 使用销售人员账号登录系统
  2. 进入 客户管理，确认仅显示自己负责的客户
  3. 进入 销售管理 → 销售订单，确认仅显示自己负责客户的订单
  4. 进入 发货申请 和 发货单，确认仅显示自己负责客户的发货信息

3.1 创建订单时自动继承

创建销售订单时，系统自动从所选客户继承 head_of_sales_id，无需手动设置。这意味着：

  • 选择客户后，订单的"销售负责人"和负责人ID自动填入
  • 编辑订单时，如果修改了"销售负责人"，系统自动匹配对应用户ID

3.2 移动端APP同步

销售订单移动端APP（client-sales）同样支持数据范围权限：

  • 选择客户后自动继承 head_of_sales_id
  • 提交订单时携带 head_of_sales_id 到后端
  • 订单列表查询受数据范围过滤限制

四、常见场景

4.1 新入职销售人员

  1. 管理员在用户管理中创建新用户，角色选择 "销售人员"
  2. 管理员在客户管理中，将需要该销售人员负责的客户编辑，选择其为"销售负责人"
  3. 销售人员登录后即可看到自己负责的客户和订单

4.2 销售人员调换客户

  1. 管理员在客户管理中，将原客户的"销售负责人"改为新的销售人员
  2. 该客户下的历史销售订单的 head_of_sales_id 不会自动变更，需根据需要手动更新
  3. 新销售人员登录后可看到该客户及后续新创建的订单
修改客户的销售负责人后，已有的销售订单不会自动更新 head_of_sales_id。如需同步历史订单，请联系系统管理员通过数据库脚本批量更新。

4.3 销售人员转岗

  1. 管理员在用户管理中，将该用户的角色从"销售人员"改为"员工"或其他角色
  2. 角色变更后，该用户不再受数据范围限制，可以看到所有数据
  3. 如有需要，将原负责的客户重新分配给其他销售人员

4.4 客户尚未指定销售负责人

如果客户的"销售负责人"字段为空（head_of_sales_id 为 NULL），则该客户数据对所有角色可见，包括销售人员。建议为所有客户都指定销售负责人以确保数据隔离完整性。

六、FAQ

Q1: 销售人员能否为客户创建订单？

可以。数据范围过滤仅作用于查看和列表，不影响创建操作。但创建后，订单会自动继承客户的 head_of_sales_id，因此只有负责该客户的销售人员能在列表中看到此订单。

Q2: 如果一个客户没有指定销售负责人会怎样？

head_of_sales_id 为 NULL 的客户对所有角色可见，包括销售人员。建议为所有客户都指定销售负责人。

Q3: 修改客户的销售负责人后，历史订单会自动更新吗？

不会。历史订单的 head_of_sales_id 在创建时从客户继承，后续修改客户的销售负责人不会自动同步到已有订单。如需同步，请联系管理员通过数据库脚本更新。

Q4: 销售人员能否查看其他客户的数据？

不能。列表、搜索、导出均受数据范围过滤限制，销售人员只能看到 head_of_sales_id 匹配自己用户ID的数据。

Q5: 销售订单仪表板统计数据是否也受限制？

是的。仪表板的订单总数、金额统计、状态分布等均按 head_of_sales_id 过滤，仅统计销售人员自己负责的订单数据。
