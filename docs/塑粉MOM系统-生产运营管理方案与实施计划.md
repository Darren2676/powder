# 睿信塑粉MOM系统 — 生产运营管理方案与实施计划

> **文档目标**：阐述基于现有 MOM 系统如何实现从销售到生产的全流程数字化运营管理，包括生产计划的 MPS/MRP 运算、生产订单的拆分与派发、BOM 备料的手工/自动称量决策，以及系统实施的项目推进顺序。

## 一、MOM 系统的制造运营管理能力

### 1.1 总体定位

睿信塑粉MOM（Manufacturing Operations Management）系统是一套覆盖塑粉制造企业**从订单到交付**全价值链的数字化管理平台。系统围绕以下六大核心管理域实现流程化、数据化的运营管控：

```
┌──────────────────────────────────────────────────────────────────────┐
│                    睿信塑粉 MOM 系统 — 六大管理域                      │
├──────────┬──────────┬──────────┬──────────┬──────────┬──────────────┤
│  销售管理 │  计划管理 │  生产管理 │  采购管理 │  库存管理 │  质量管理    │
│          │          │          │          │          │              │
│ 销售订单  │ MPS 主计 │ 生产工单  │ 采购申请  │ 原料库存  │ 来料检验     │
│ 销售预测  │ 划       │ 工序任务  │ 采购订单  │ 成品库存  │ 生产检验     │
```

### 2.2 MPS 主生产计划计算逻辑

MPS（Master Production Schedule）接收两类需求来源：

- **销售订单**（`sales_order`）：已审批、remaining_quantity > 0
- **销售预测**（`sales_forecast`）：已审批、remaining_quantity > 0

计算规则：

```
gross_demand = MAX(forecast_demand, order_demand)

net_demand   = MAX(0, gross_demand
                    - finished_goods_on_hand    -- 成品现有库存
                    - finished_goods_in_transit -- 成品在途（发货未确认）
                    - production_in_transit     -- 生产在途（已排产未入库）
                    + finished_goods_safety_stock) -- 成品安全库存
```

当 `net_demand > 0` 时，系统自动生成生产计划，供计划员提交审批。

### 2.3 MRP 运算核心机制

MRP（Material Requirements Planning）采用**广度优先分层分解算法**，从成品（Level 0）出发，沿 BOM 结构逐层展开：

| 层级 | 处理对象 | 核心逻辑 |
|------|---------|---------|
| **Level 0** | 成品 | 不计算净需求，直接按计划数量写入 MRP 结果，确保生产单必定生成 |
| **Level 1** | 半成品/原料 | 需求归集 → 查 `material_inventory` 库存 → 计算净需求 |
| **Level 2+** | 深层子件 | 同上，递归展开直到无 BOM 或净需求 ≤ 0 |

**子件净需求计算公式**：

```
net = MAX(0, gross - (on_hand + wip + in_transit_po + pending_pr) + safety_stock)
```

### 2.4 行动类型决策与订单下达

MRP 对每个物料的行动类型决策：

| 条件 | action_type | 结果 |
|------|------------|------|
| `business_scope = '生产'` | 生产 | 生成生产工单 |
| `business_scope = '采购'` | 采购 | 生成采购申请 |
| `business_scope = '生产+采购'` | 生产+采购 | 双源待决策，计划员手动分配数量 |
| `business_scope IS NULL` + 有 BOM | 生产 | 按自制处理 |
| `business_scope IS NULL` + 无 BOM | 采购 | 按外购处理 |

MRP 确认执行后，系统自动：
- 生成 `production_order`（生产工单，状态：草稿/未开始）
- 生成 `purchase_req`（采购申请，合并所有采购行到一张单）
- 更新源计划状态：`mrp_status = '已分解'`, `plan_status = '已加入任务'`

## 三、生产单分解与备料称量决策

### 3.1 生产单的"每缸"分解

塑粉行业的生产以**每缸**（每批次）为单位进行。计划员需要根据：

- **设备每缸最大生产数量**（由设备/模具能力决定）
- **销售订单的物料数量**

将一个大数量的生产单**人为拆分为多个子生产单**，每个子生产单对应一缸的生产量。

```
  销售订单: C100809-TJ × 10,000 kg
         │
         ▼
  每缸最大生产量: 1,200 kg
         │
         ▼
  拆分结果:
    ├── 生产单 #1: C100809-TJ × 1,200 kg（缸1）
    ├── 生产单 #2: C100809-TJ × 1,200 kg（缸2）
    ├── 生产单 #3: C100809-TJ × 1,200 kg（缸3）
    ├── ...（8缸 × 1,200 kg）
    └── 生产单 #9: C100809-TJ × 400 kg（尾缸）
```

**系统支撑**：MOM 系统提供生产单拆分功能，支持从已审批的生产单中按数量拆分为多个子生产单，原单数量自动扣减。

### 3.2 BOM 备料清单生成

生产单审批后，计划员进行**派发操作**，系统自动：

1. 根据生产单关联的 **制造 BOM**（`mfg_bom_header` + `mfg_bom_detail`）
2. 按**倍率**（planned_quantity / BOM 基数量）计算每种物料的需求量
3. 生成**备料单**（`material_preparation`）和**倒冲任务**（`backflush_task`）

```
倍率 = planned_quantity / bom_base_quantity

物料需求量 = 倍率 × BOM明细中的 actual_quantity

备料单编号: MP-YYYYMMDD-NNN
```

### 3.3 自动称量 vs 手工称量决策

备料清单中的每种物料，需要判断是**自动称量**还是**手工称量**：

```
                    备料清单物料
                         │
                         ▼
              ┌─────────────────────┐
              │  BOM 中是否设定为      │
              │  可自动称量的材料？     │
              └──────────┬──────────┘
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
          是(auto_weigh='Y')    否(auto_weigh='N')
              │                     │
              ▼                     ▼
      ┌───────────────┐    ┌───────────────┐
      │ 计划员二次判定   │    │  手工称量       │
      │               │    │  (人工操作)     │
      └───────┬───────┘    └───────────────┘
              │
    ┌─────────┴─────────┐
    ▼                   ▼
 称量精度满足        称量精度不满足
 (小药量过大/         (小药量过小，
  精度可接受)         需要更高精度)
    │                   │
    ▼                   ▼
┌─────────┐      ┌───────────┐
│ 自动称量 │      │ 手工称量    │
│ → 接口   │      │ (人工操作)  │
│ 传递小药 │      │            │
│ 称量系统 │      │            │
└─────────┘      └───────────┘
```

**关键决策点**：

1. **BOM 层面**：在 BOM 明细中设定物料是否"可自动称量"。这是材料属性层面的初步判断。
2. **计划员层面**：由于部分小药（添加剂、颜料等）的**称量精度要求**极高，即使 BOM 中标记为"可自动称量"，计划员也需要根据**实际生产经验**进行二次判定：
   - 当小药的**单次称量克数极小**时，自动称量设备可能无法满足精度要求 → 改为手工称量
   - 当小药的**单次称量克数在设备精度范围内**时 → 保持自动称量

**系统支撑**：MOM 系统的倒冲任务清单（`backflush_task`）中包含 `auto_weigh` 字段（Y/N），计划员可以在备料清单页面**批量切换**每项物料的自动/手工称量标记。

### 3.4 自动称量接口

当备料物料被标记为"自动称量"后，系统通过接口将称量任务传递给**小药称量系统**：

```
┌──────────────┐        接口传递         ┌──────────────────┐
│  MOM 系统     │ ──────────────────────→ │  小药自动称量系统  │
│              │   物料编号、称量重量、     │                  │
│  backflush_  │   批次号、生产单号        │  自动称量设备执行  │
│  task        │                          │  称量并反馈结果    │
│  auto_weigh  │ ←────────────────────── │                  │
│  = 'Y'       │    称量结果、实际重量     │                  │
└──────────────┘                         └──────────────────┘
```

传递数据包括：
- 物料编号（`material_number`）和物料名称
- 需求称量重量（`required_quantity`）
- 生产单号（`production_order_number`）
- 工序/工位信息（`step_number`, `work_center`）
- 仓库信息（`warehouse_number`）

## 五、项目实施的先后顺序

### 5.1 实施原则

基于**运营管理的依赖关系**，整个项目的实施遵循"数据基础 → 业务主干 → 精细化扩展"的路径。核心判断依据：

> 生产单的生成依赖 BOM 和 MRP 运算结果；备料清单中手工/自动称量的决策依赖生产单和 BOM 明细设定。因此，**BOM → 生产计划 → MRP → 生产单 → 备料清单**是必须优先建设的主链路。

### 5.2 分阶段实施计划

#### 第一阶段：基础数据建设（优先级：⭐⭐⭐⭐⭐ 最高）

| 序号 | 实施内容 | 说明 | 完成标志 |
|------|---------|------|---------|
| 1.1 | 物料主数据维护 | 所有原材料、半成品、成品的物料编码、规格、单位、业务范围（`business_scope`）入库 | 物料主数据完整率 ≥ 95% |
| 1.2 | BOM 搭建 | 建立所有成品的**制造BOM**（含层级关系、用量、工序关联） | 全部量产产品 BOM 就绪 |
| 1.3 | 工厂/车间/仓库/设备基础数据 | 组织结构数据、仓储位置、设备台账 | 基础档案完整 |
| 1.4 | 工艺路线配置 | 每道工序的标准工艺、默认工位、倒冲设定 | 工序路线完整 |
| 1.5 | 供应商/客户档案 | 上下游业务伙伴数据 | 档案数据完整 |

**前置依赖**：无，这是后续所有业务的**数据地基**。

---

#### 第二阶段：销售与计划主链路（优先级：⭐⭐⭐⭐⭐ 最高）

| 序号 | 实施内容 | 说明 | 完成标志 |
|------|---------|------|---------|
| 2.1 | 销售订单管理 | 销售人员录入订单 → 审批 → 跟踪执行状态 | 销售订单全流程贯通 |
| 2.2 | MPS 主生产计划 | 系统自动汇总销售需求，计算净需求，生成生产计划建议 | MPS 运算结果可审核可确认 |
| 2.3 | MRP 物料需求运算 | 广度优先 BOM 分解，自动生成生产单和采购申请 | MRP 运算结果准确可执行 |
| 2.4 | 双源物料决策 | 计划员对"生产+采购"物料分配自制/外购数量 | 双源决策流程完整 |
| 2.5 | 生产计划审批流程 | 草稿 → 提交 → 审批 → 已审批 | 审批流程闭环 |

**前置依赖**：第一阶段（物料主数据、BOM、工艺路线）

---

#### 第三阶段：生产执行与备料称量（优先级：⭐⭐⭐⭐ 高）

| 序号 | 实施内容 | 说明 | 完成标志 |
|------|---------|------|---------|
| 3.1 | 生产单拆分（每缸） | 计划员输入每缸最大数量，系统辅助拆分子生产单 | 拆分功能可用，子单关联清晰 |
| 3.2 | 生产单审批与派发 | 提交审批 → 派发 → 生成工序任务 + 备料单 | 派发自动生成工序和备料 |
| 3.3 | 备料清单管理 | 查看每缸备料明细，确认需求量 | 备料清单可视化 |
| 3.4 | **自动称量标记管理** | BOM中设定默认自动称量；计划员在备料清单中二次判定（考虑小药称量精度），批量切换 auto_weigh | 手工/自动称量决策流程完整 |
| 3.5 | **小药称量系统接口** | 将 auto_weigh='Y' 的备料任务通过接口传递给小药自动称量系统，接收称量结果反馈 | 接口联调通过，数据双向同步 |
| 3.6 | 手工称量任务管理 | auto_weigh='N' 的备料任务分配给人工称量岗位 | 手工称量任务可跟踪 |

**前置依赖**：第二阶段（MRP → 生产单），以及小药称量系统的 API 接口开发

## 六、总结

本方案以**睿信塑粉MOM系统**现有能力为基础，围绕以下核心逻辑构建了完整的运营管理解决方案：

1. **流程化**：销售 → MPS → MRP → 生产/采购 → 备料称量 → 入库，全链路贯通
2. **数据化**：每个岗位的日常操作沉淀为基础数据，驾驶舱和报告辅助快速决策
3. **智能化**：MRP 自动运算分解 BOM，区分自制/采购/双源决策
4. **精细化**：每缸拆分、自动/手工称量二级决策、小药称量精度把关

实施顺序严格遵循业务依赖关系：**先建数据地基，再通主业务链，后做精细化扩展**，确保每个阶段都有明确的可交付成果和业务价值。
