生产报工·检验·撤销重报全流程逻辑流程图

睿信橡胶密封件MES系统 | 从生产单派发→备料出库→按工序报工→检验门控→检验执行→报错撤销重报的全链路业务逻辑，含完整门控规则与删除约束
文档说明：本文档聚焦生产执行核心链路：报工、检验、错误撤销与重报，涵盖6个阶段：
阶段1 生产单派发到备料 — 计划状态流转与物料齐套
阶段2 报工全链路门控 — 9道门控校验确保数据合法性
阶段3 检验单自动创建与检验执行 — 自检/专检触发、质量特性/缺陷记录
阶段4 检验门控与工序阻塞 — 必须先检验才能下一道报工
阶段5 删除门控规则 — 只能从后道工序依次向前删除（新增核心规则）
阶段6 撤销重报完整流程 — 入库撤回→拆箱→级联删除→重新报工

5.3 删除顺序示例

场景：生产单有工序10（硫化）、20（修边）、30（检验），每道工序均有报工记录和检验单。

正确删除顺序：
① 先删除工序30的检验单 → ② 再删除工序30的报工单 →
③ 然后删除工序20的检验单 → ④ 再删除工序20的报工单 →
⑤ 最后删除工序10的检验单 → ⑥ 再删除工序10的报工单

❌ 错误操作：直接删除工序10的报工单（报错：存在更高工序20/30的报工记录）

5.4 门控规则与代码对照

门控项报工删除检验单删除错误提示
更高工序检查 SELECT TOP 1 step_number FROM work_report WHERE step_number > currentStep SELECT TOP 1 step_number FROM production_inspection WHERE step_number > currentStep 该生产单存在更高工序(X)的报工/检验记录，只能从后道工序依次向前删除。请先删除工序X的报工/检验记录。
同工序更晚记录检查 SELECT TOP 1 FROM work_report WHERE step_number = currentStep AND creation_date > 当前记录的creation_date SELECT TOP 1 FROM production_inspection WHERE step_number = currentStep AND creation_date > 当前记录的creation_date 该工序存在更晚的报工/检验记录，只能删除最后一条记录。
关联检验单检查（仅报工删除） SELECT TOP 1 status FROM production_inspection WHERE work_report_number = 当前报工单号 — 已完成检验: 请先通过撤销重报回退；待检/检验中: 请先删除检验记录
已完成状态检查（仅检验单删除） — status='已完成' → 403 已完成的检验记录不允许删除。如需撤销，请使用撤销重报功能。

六、撤销重报完整流程

场景说明：生产过程中，发现工序N的报工数据有误，但后道工序N+1、N+2等已经报工。撤销重报从目标工序开始，逆向删除该工序及所有后道工序的报工单和检验单，然后重新报工。
API入口：POST /api/v1/work-reports/undo-preview（预览影响范围）→ POST /api/v1/work-reports/undo-execute（执行撤销）
