## 一、销售管理（ERP 迁移）

### 1.1 功能概述

将现有 ERP 系统中的销售业务流程迁移至 MOM 系统，实现从**销售订单 → 发货 → 退货 → 对账 → 开票**的端到端管理，并与生产计划模块联动。

### 1.2 业务流程图

```
                    销售订单下达
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
      生产计划联动    直接发货       销售退货
      (MPS/MRP)         │              │
                        ▼              ▼
                    发货单          退货单
                  (shipping_       (sales_
                   order)          return)
                        │              │
                        ▼              │
                    客户签收          │
                        │              │
                ┌───────┴───────┐      │
                ▼               ▼      │
           ┌─────────┐    ┌─────────┐  │
           │ 销售对账 │    │ 销售开票 │  │
           │ (recon- │    │ (sales_ │  │
           │ ciliation)│   │ invoice)│  │
           └────┬────┘    └────┬────┘  │
                │              │       │
                └──────┬───────┘       │
                       ▼               │
              ┌────────────────┐       │
              │   发票勾稽关联  │       │
              │ 发票 ↔ 发货单  │       │
              │ 发票 ↔ 销售订单 │       │
              └────────────────┘       │
                                       │
                      财务应收确认 ◄────┘
```

### 1.3 核心数据实体关系

```
sales_order (销售订单)
    │  1:N
    ├──→ sales_order_detail (订单明细)
    │       │ 1:N
    │       └──→ shipping_order_detail (发货明细)
    │               │ N:1
    │               └──→ shipping_order (发货单)
    │                       │ 1:N
    │                       └──→ sales_invoice_line (发票明细)
    │                               │ N:1
    │                               └──→ sales_invoice (销售发票)
    │
    └──→ sales_return (退货单)
```

### 1.4 关键业务规则

| 业务环节 | 规则说明 | 现有状态 |
|---------|---------|---------|
| **销售订单下达** | 录入客户、物料、数量、单价、交期；审批后生效 | ✅ 已实现 |
| **发货管理** | 根据订单创建发货单，支持部分发货；记录签收状态 | ✅ 已实现 |
| **退货管理** | 关联原销售订单，退货数量冲减已发货量 | ✅ 已实现 |
| **客户对账** | 根据发货明细逐行标记对账状态：`reconciliation_status` = 已对账 / 未对账 | ✅ 已实现 |
| **销售发票** | 关联发货单明细和销售订单明细，支持部分开票 | ✅ 已实现 |
| **发票勾稽** | 发票行关联发货明细（`shipping_detail_id`）和销售订单明细（`sales_detail_id`），实现三单关联 | ✅ 已实现 |
| **开票状态同步** | 发票生成后回写发货明细 `invoice_status`（未开票→已开票/部分开票） | ✅ 已实现 |

### 1.5 对账与发票勾稽详细流程

```
  发货单明细 (shipping_order_detail)
       │
       ├── reconciliation_status = '已对账'   ← 客户确认收货后标记
       │
       └── invoice_status = '已开票'          ← 开票后系统自动更新
              │
              ▼
  销售发票行 (sales_invoice_line)
       ├── shipping_order_number   ← 关联发货单号
       ├── shipping_detail_id      ← 关联发货明细行 (勾稽)
       └── sales_detail_id         ← 关联销售订单明细行 (勾稽)
```

**对账操作**：
- 在销售发货页面，选择已签收的发货明细行
- 批量更新 `reconciliation_status` 为"已对账"
- 系统记录对账时间和操作人

**发票勾稽**：
- 创建销售发票时，选择已对账但未开票的发货明细
- 发票行自动关联 `shipping_detail_id` 和 `sales_detail_id`
- 发票保存后回写发货明细的 `invoice_status`

            │       └──→ stock_in_detail (入库明细)
            │               │ N:1
            │               └──→ stock_in (入库单/收货单)
            │                       │ 1:N
            │                       └──→ purchase_invoice_line (发票明细)
            │                               │ N:1
            │                               └──→ purchase_invoice (采购发票)
            │
            └──→ purchase_return (退货单)
```

### 2.4 关键业务规则

| 业务环节 | 规则说明 | 现有状态 |
|---------|---------|---------|
| **采购订单下达** | 支持 MRP 自动生成采购申请转订单，也支持手工创建 | ✅ 已实现 |
| **收货入库** | 根据采购订单收货，条件触来来料检验 | ✅ 已实现 |
| **来料检验** | `item_master.incoming_inspection = 'Y'` 时自动创建检验单 | ✅ 已实现 |
| **退货管理** | 关联原采购订单/收货单 | ✅ 已实现 |
| **供应商对账** | 收货明细逐行标记 `reconciliation_status`（已对账/未对账） | ✅ 已实现 |
| **采购发票** | 关联收货单明细（`stock_in_detail`）和采购订单明细 | ✅ 已实现 |
| **发票勾稽** | 发票行 ↔ 收货明细 ↔ 采购订单明细 三级关联 | ✅ 已实现 |

## 三、仓库管理（ERP 迁移）

### 3.1 功能概述

迁移 ERP 中原材料仓库和成品仓库的完整管理功能，支持**入库、出库、移库、盘点、库存查询、批次管理**。

### 3.2 仓库类型

| 仓库类型 | 数据库表 | 说明 |
|---------|---------|------|
| **原材料仓** | `material_inventory` | 存储采购入库的原材料，支持批次号和有效期 |
| **成品仓** | `finished_goods_inventory` | 存储生产完成的成品 |
| **线边仓** | `lineside_inventory` | 从原料仓移入生产线边的物料，倒冲出库 |
| **报废仓** | 通过入库类型区分 | 不合格品报废指定仓库 |
| **备料仓** | 通过入库类型区分 | 已备料待生产的物料暂存 |

### 3.3 核心功能清单

| 功能 | 说明 | 现有状态 |
|------|------|---------|
| **采购入库** | 采购收货 → 质检 → 入库确认 → 批次号生成 | ✅ 已实现 |
| **生产入库** | 工序报工 → 检验 → 成品入库 → 批次号生成 | ✅ 已实现 |
| **线边仓移入** | 原料仓 → 线边仓，按生产单移料 | ✅ 已实现 |
| **倒冲出库** | 成品入库时自动扣减线边仓库存 | ✅ 已实现 |
| **库存盘点** | 定时/手动盘点，盘盈盘亏处理 | ✅ 已实现 |
| **库存流水** | `material_inventory_transaction` 记录所有出入库操作 | ✅ 已实现 |
| **批次管理** | 入库自动生成批次号，按批次追踪 | ✅ 已实现 |
| **有效期管理** | 基于批次生产日期/入库日期 + 有效天数，到期/即将到期预警 | ✅ 已实现 |
| **安全库存** | 设定安全库存量，低于阈值预警 | ✅ 已实现 |
| **库存查询** | 按物料/仓库/批次多维度查询 | ✅ 已实现 |

### 3.4 批次号规则

系统支持**双模式**批次号生成：

| 模式 | 规则 | 适用场景 |
|------|------|---------|
| **日期流水模式** | `YYYYMMDD` + 流水号 | 标准批次管理 |
| **自定义规则模式** | 按产品批次号产生规则配置 | 特殊产品追溯需求 |

## 四、产品生命周期管理（新建）

### 4.1 模块总体架构

产品生命周期管理（PLM）覆盖从**样品申请 → 配方研发 → 试制验证 → 量产转化 → 成本管控**的全过程。

```
                       产品生命周期管理
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
  ┌──────────┐      ┌──────────────┐     ┌──────────────┐
  │ 样品管理  │      │ BOM 版本管理  │     │ 材料成本管理  │
  │          │      │              │     │              │
  │ · 样品申请│      │ · 样件BOM    │     │ · 标准成本    │
  │ · 配方BOM │      │ · 生产BOM    │     │ · BOM成本计算 │
  │ · 特性参数│      │ · 版本追溯    │     │ · 成本快照    │
  │ · 转化KPI │      │ · BOM转化    │     │              │
  └──────────┘      └──────────────┘     └──────────────┘
```

### 4.2 样品管理

#### 4.2.1 业务流程

```
  客户需求 / 内部研发需求
         │
         ▼
  ┌──────────────┐
  │  样品申请提交  │  ← 销售/技术提交 sample_request
  │  · 客户信息    │     urgency: 正常/紧急/特急
  │  · 物料类型    │
  │  · 数量/单位   │
  │  · 紧急程度    │
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │  技术部评审    │  ← 审批通过后进入研发
  └──────┬───────┘
         │
         ▼
  ┌──────────────────────────────────┐
  │         配方 BOM 建立             │
  │  · sample_bom_header: 样件BOM主表 │
  │  · sample_bom_version: 版本管理   │
  │  · sample_bom_detail: 配方明细    │
  │  · 物料配比 / 工艺参数 / 特性值    │
  └──────────────┬───────────────────┘
         │
         ▼
  ┌──────────────┐      ┌──────────────┐
  │  样品试制     │  ←→  │  BOM 版本迭代 │
  │  (试制工单)   │      │  V1 → V2 → V3 │
  └──────┬───────┘      └──────────────┘
         │
         ▼
  ┌──────────────┐
  │  样品送样/测试 │
  │  · 样品检验    │
  │  · 性能测试    │
  │  · 客户确认    │
  └──────┬───────┘
         │
         ├── 客户确认 → 转小批验证
         ├── 客户不通过 → 调整配方，新版本
         └── 记录转化率 KPI
```

#### 4.2.2 样件 BOM 版本管理

| 功能 | 说明 | 现有状态 |
|------|------|---------|
| **样件 BOM 主表** | `sample_bom_header`：BOM 编号、BOM 名称、关联样品申请号 | ✅ 已实现 |
| **BOM 版本管理** | `sample_bom_version`：版本号、版本状态（草稿/已锁定/已发布）、生效日期 | ✅ 已实现 |
| **配方明细** | `sample_bom_detail`：物料编号、用量、工序号、备注 | ✅ 已实现 |
| **特性参数** | 样件 BOM 关联的特性参数（颜色、光泽度、粒径分布、胶化时间等） | ⚠️ 待扩展 |
| **版本差异对比** | 不同版本之间的配方差异分析 | ⚠️ 待开发 |

#### 4.2.3 样品转化率 KPI

```
样品转化率 = 转化为量产配方的样品数 / 总样品申请数 × 100%

统计维度：
  · 按时间段（月度/季度/年度）
  · 按客户
  · 按产品类型
  · 按技术负责人
```

### 4.3 样件 BOM 转化为生产 BOM

#### 4.3.1 转化流程

```
  样件 BOM (sample_bom)
  · 配方比例 (实验级)
  · 实验室工艺参数
         │
         ▼  小批验证 / 中试
  ┌─────────────────────────┐
  │  BOM 转化过程记录         │
  │  · 配方比例微调记录       │
  │  · 工艺参数调整记录       │
  │  · 设备适配调整           │
  │  · 定额与实际差异分析      │
  └───────────┬─────────────┘
              │
              ▼
  生产 BOM (mfg_bom)
  · 标准配方比例
  · 量产工艺参数
  · 与工艺路线关联
  · 自动称量标记设定
```

#### 4.3.2 关键转化规则

| 转化项 | 样件 BOM | 生产 BOM | 调整依据 |
|--------|---------|---------|---------|
| **物料用量** | 实验室基准量 | 量产基准量（含损耗系数） | 中试验证数据 |
| **工艺参数** | 实验条件参数 | 量产设备工艺参数 | 设备能力匹配 |
| **工序关联** | 无工序关联 | 关联工艺路线工序号 | 生产流程确定 |
| **自动称量标记** | 不设定 | 设定材料是否可自动称量 | 材料属性 + 称量精度 |
| **默认仓库** | 不设定 | 设定线边仓/原料仓 | 物流路径确定 |

### 4.4 BOM 材料成本管理

#### 4.4.1 成本计算体系

```
原材料标准成本 (item_master / standard_cost_detail)
         │
         ▼
  ┌─────────────────────────────┐
  │        BOM 材料成本计算       │
  │  BOM成本 = Σ(物料标准单价      │
  │            × BOM单位用量)      │
  └─────────────┬───────────────┘
                │
    ┌───────────┼───────────┐
    ▼           ▼           ▼
  生产单      生产计划     销售订单
  材料成本    材料成本     材料成本
                │
                ▼
  ┌─────────────────────────────┐
  │  生产物料成本快照              │
  │  production_material_cost_   │
  │  snapshot                    │
  │  · 标准用量 × 标准单价        │
  │  · 用于成本核算与分析          │
  └─────────────────────────────┘
```

#### 4.4.2 成本数据流

```
  standard_cost_header (标准成本单价表)
      │
      ├── cost_list_number: 成本表编号
      ├── effective_date: 生效日期
      ├── expiration_date: 失效日期
      │
      └──→ standard_cost_detail (成本明细)
              ├── item_number: 物料编号
              ├── standard_cost: 标准单价
              ├── actual_cost: 实际成本
              └── material_type: 物料类型
                      │
                      ▼
              ┌──────────────────┐
              │  成本 BOM 计算    │
              │  (计划物料成本)   │
              │  planMaterialCost │
              └──────────────────┘
```

#### 4.4.3 成本应用场景

| 应用场景 | 成本数据来源 | 计算方式 | 现有状态 |
|---------|------------|---------|---------|
| **生产计划材料成本** | BOM × 标准单价 | SUM(各物料标准单价 × 单位用量) × 计划数量 | ✅ 已实现 |
| **销售订单材料成本** | 关联生产计划 → BOM | 同上，按订单数量比例分摊 | ✅ 已实现 |
| **生产单实际材料成本** | 实际领用量 × 实际单价 | SUM(实际领用量 × 移动平均价) | ⚠️ 待完善 |
| **成本差异分析** | 标准 vs 实际 | (实际成本 − 标准成本) / 标准成本 × 100% | ⚠️ 待开发 |

## 五、生产计划管理（核心升级）

### 5.1 从销售订单到生产执行的完整链路

```
销售订单 (sales_order)
    │ approval_status = '已审批'
    ▼
MPS 主生产计划计算
    │ net = MAX(0, gross − on_hand − in_transit
    │          − prod_in_transit + safety_stock)
    ▼
生产计划 (Production_plan)
    │ approval_status: 草稿 → 已审批
    │ plan_status: 待加入任务
    ▼
计划员人工拆分
    │ 根据每缸最大产量拆分为多个生产单
    ▼
生产单 (production_order)
    │ 每缸一个生产单
    ▼
MRP 物料需求计划
    │ BFS 广度优先 BOM 分解
    │ action_type 决策: 生产 / 采购 / 双源
    ▼
┌──────────────────┬──────────────────┐
│  action_type=生产  │  action_type=采购  │

### 5.2 生产领料清单与小药称量决策

#### 5.2.1 备料清单生成规则

生产单派发时，系统自动从生产 BOM 展开备料清单：

```
倍率 = planned_quantity / bom_base_quantity

每种物料需求量 = 倍率 × BOM 明细中的 actual_quantity

工序信息: 从工艺路线明细的物料映射表获取 step_number
工位信息: 从已生成的工序任务获取 work_center
仓库信息: 工艺路线倒冲仓库 → 工序默认仓库 → BOM 默认仓库
```

#### 5.2.2 自动称量 vs 手工称量决策

```
         BOM 预设 auto_weigh 标记
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   auto_weigh = 'Y'        auto_weigh = 'N'
   (可自动称量)             (不可自动称量)
        │                       │
        ▼                       ▼
  ┌─────────────┐        ┌─────────────┐
  │ 计划员二次判定│        │  手工称量    │
  │             │        │  (固定)      │
  └──────┬──────┘        └─────────────┘
         │
  ┌──────┴──────┐
  ▼             ▼
精度满足      精度不满足
(克数在设备    (小药克数极小
 精度范围内)    需更高精度)
  │             │
  ▼             ▼
自动称量       改为手工称量
 → 小药称量     (计划员在备料清单
   系统接口      页面批量切换标记)
```

**关键设计**：
- BOM 层面设定的是"材料是否**适合**自动称量"（静态属性）
- 计划员层面判断的是"本次生产的小药**单次称量克数**是否在设备精度范围内"（动态判断）
- 两层叠加形成最终决策

### 5.3 基于成本 BOM 的成本计算

#### 5.3.1 成本数据关联链路

```
销售订单 (sales_order)
    │ sales_order_detail
    ▼
生产计划 (Production_plan)
    │ 关联销售订单
    ▼
生产单 (production_order)
    │ 关联生产BOM (mfg_bom)
    ▼
成本BOM数据
    │ standard_cost_detail
    │ × BOM用量
    ▼
┌─────────────────────────────────┐
│  production_material_cost_snapshot │
│  · production_order_number          │
│  · cost_list_number                 │

│  · standard_cost (标准成本)          │
└─────────────────────────────────┘
         │
         ▼
  计划物料成本报表 (planMaterialCost)
```

#### 5.3.2 成本计算公式

| 成本类型 | 计算公式 |
|---------|---------|
| **BOM 材料成本** | Σ(每种物料标准单价 × BOM 单位用量) |
| **生产单材料成本** | Σ(每种物料标准单价 × 需求数量) |
| **生产计划材料成本** | Σ(关联生产单材料成本) |
| **销售订单材料成本** | Σ(关联生产计划材料成本按订单比例) |

#### 6.3.1 SPC 分析维度

| 分析维度 | 数据来源 | 分析内容 |

#### 6.3.2 SPC 控制图类型

| 控制图 | 适用场景 |
|--------|---------|
| **X̄-R 控制图** | 计量型数据，分组样本（如每批抽 3-5 件） |
| **X̄-S 控制图** | 计量型数据，样本量较大 |
| **I-MR 控制图** | 单值数据（如每批只测一次） |
| **P 控制图** | 计数型不合格品率 |
| **C 控制图** | 计数型缺陷数 |

#### 6.3.3 SPC 判定规则

基于 Western Electric Rules（西部电气规则）：

1. 任一点超出 ±3σ 控制限
2. 连续 7 点在中心线同侧
3. 连续 7 点上升或下降
4. 连续 3 点中有 2 点在 ±2σ 之外
5. 其他异常模式

### 6.5 有效期管理

| 设定位置 | 字段 | 说明 |
|---------|------|------|
| `item_master` | `shelf_life_enabled` | 是否启用有效期管理 |

| `batch_inventory` | `production_date` | 批次生产日期（起点） |
| `batch_inventory` | `expiry_date` | 到期日期（计算值） |

#### 6.5.2 到期预警机制

```
到期判定:
  expiry_date = production_date + shelf_life_days

预警规则:
  · 已到期:      expiry_date < 当前日期
  · 即将到期:    expiry_date − warning_days < 当前日期 < expiry_date
  · 正常:        当前日期 < expiry_date − warning_days

预警天数: 默认可配置（如 30 天前预警）
```

#### 6.5.3 有效期报告

系统提供 `shelfLifeReport` 模块，按物料类型分别展示原材料和成品的：

- 当前库存数量
- 批次号
- 生产日期 / 入库日期
- 到期日期
- 到期状态（已到期 🟡 / 即将到期 🔴 / 正常 🟢）
- 剩余天数

### 8.5 项目风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| ERP 数据迁移不完整 | 业务中断 | 分批迁移、并行运行、数据校验 |
| 用户习惯变更抵触 | 推广困难 | 充分培训、过渡期 ERP+MOM 并行 |
| 小药称量接口联调延迟 | 阶段2延期 | 提前与称量设备供应商沟通接口规范 |
| SPC 算法复杂度 | 阶段3延期 | 分阶段交付：先做基础控制图，再做高级分析 |
| 多工厂网络延迟 | 用户体验差 | 集团报表采用异步汇总，非实时查询 |

## 九、总结

本文档梳理了睿信塑粉MOM系统的七大核心功能体系：

| 模块 | 定位 | 核心价值 |
|------|------|---------|
| **销售管理** | ERP 迁移 | 订单→发货→对账→发票 全链条闭环 |
| **采购管理** | ERP 迁移 | 订单→收货→对账→发票 全链条闭环 |
| **仓库管理** | ERP 迁移 | 原料/成品/线边仓 多仓联动 |
| **产品生命周期** | 新建 | 样品→配方→试制→量产 全生命周期 |
| **生产计划** | 核心升级 | MPS→MRP→备料→称量 智能决策 |
| **质量管理** | 新建 | 来料+生产检验 → SPC → 追溯 |
| **集团管理** | 新建 | 多工厂隔离 + 集团汇总报表 |

实施遵循**"先迁移基础、再升级核心、后扩展体系"**的四阶段路径，确保每个阶段都有可验证的业务价值和明确的交付标准。
