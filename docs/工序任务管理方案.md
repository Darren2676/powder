# 工序任务管理方案

## 一、系统概述

工序任务管理是 Seals MES System 生产执行层的核心模块，位于业务链条中承上启下的位置：

```
主生产计划 → 生产单 → 【工序任务单】 → 报工单
                ↓              ↓
            工艺路线         领料单
            (拆解依据)     (物料发放)
```

**核心功能：** 将一张"生产单"按照其关联的"工艺路线"自动拆解为多条"工序任务"，每条工序任务对应一道具体生产工序，是车间作业调度、报工、领料的最小执行单元。

## 二、业务流程

### 2.1 工序任务生成流程

```
┌─────────────┐      ┌─────────────────┐      ┌──────────────────┐
│  生产单      │      │  工艺路线主表    │      │  工艺路线明细    │
│  (已审批)    │ ───→ │  routing_header  │ ───→ │  routing_detail   │
│             │      │  (按产品编号匹配) │      │  (N条工序明细)   │
└──────┬──────┘      └─────────────────┘      └────────┬─────────┘
       │                                               │
       │              自动拆解                          │
       └──────────────────┬────────────────────────────┘
                          ↓
              ┌───────────────────────┐
              │    工序任务单          │
              │    process_task       │
              │  (每道工序一条记录)    │
              └───────────────────────┘
```

### 2.2 完整业务场景

**场景1：从生产单自动拆解工序任务**

1. 生产单审批通过（approval_status = '已审批'）
2. 用户在工序任务管理页面点击"从生产单导入"
3. 弹窗显示已审批的生产单列表，用户勾选要拆解的生产单
4. 系统根据生产单的产品编号 `item_number` 匹配工艺路线主表 `routing_header`
5. 读取工艺路线明细 `routing_detail`，按工序序号逐条生成工序任务
6. 每条工序任务继承生产单的计划数量、产品信息，以及工序的工作中心、物料投入等
7. 生成结果返回统计（成功N条，跳过N条）

**场景2：手动创建工序任务**

1. 用户点击"新建"，手动填写工序任务信息
2. 选择关联的生产单编号（可选），选择工序信息
3. 保存后状态为"草稿"，可提交审批

**场景3：工序任务执行与报工**

1. 工序任务审批通过，状态变为"已审批"
2. 车间操作员根据工序任务进行作业
3. 作业完成后通过"报工单"模块进行报工（后续模块）
4. 工序任务状态跟踪：未开始 → 进行中 → 已完成

### 4.4 从生产单拆解生成（核心接口）

**请求：**
```json
POST /process-tasks/generate-from-order
{
  "production_order_numbers": ["P20260319001", "P20260319002"]
}
```

**处理逻辑：**
```
1. 遍历每个生产单编号
2. 校验生产单存在且 approval_status = '已审批'
3. 通过 item_number 匹配 routing_header（condition = '启用', approval_status = '已审批'）
4. 读取匹配的 routing_detail 明细，按 step_number 排序
5. 逐条生成 process_task 记录：
   - process_task_number: 自动生成 PT-YYYYMMDD-NNN
   - 继承生产单字段: production_order_number, production_number, item_number, item_name, specifications, basic_unit, planned_quantity
   - 继承工序字段: process_route_number, step_number, standard_process_number/name, work_center_number/name, 物料投入字段, 损耗率, 配料方式, 超额报工比例
   - 初始化字段: completed_quantity=0, task_status='未开始', approval_status='草稿'
   - 自动字段: creation_date=当前时间, creation_man=当前用户
6. 返回生成统计
```

**响应：**
```json
{
  "success": true,
  "message": "成功从 2 张生产单生成 12 条工序任务",
  "data": {
    "orderCount": 2,
    "taskCount": 12,
    "details": [
      { "production_order_number": "P20260319001", "tasks_generated": 6 },
      { "production_order_number": "P20260319002", "tasks_generated": 6 }
    ],
    "skipped": []
  }
}
```

**异常处理：**

| 场景 | 处理 |
|------|------|
| 生产单不存在 | 跳过，记入 skipped |
| 生产单未审批 | 跳过，提示"生产单未审批" |
| 未匹配到工艺路线 | 跳过，提示"未找到匹配的工艺路线" |
| 工艺路线未启用/未审批 | 跳过，提示"工艺路线未启用或未审批" |
| 工艺路线无明细工序 | 跳过，提示"工艺路线无工序明细" |
| 插入失败 | 跳过该条，继续下一条 |

## 七、核心拆解算法

### 7.1 从生产单生成工序任务（伪代码）

```typescript
async function generateFromOrder(orderNumbers: string[], currentUser: string) {
  const results = { orderCount: 0, taskCount: 0, details: [], skipped: [] };

  for (const orderNo of orderNumbers) {
    // 1. 查询生产单
    const order = await query("SELECT * FROM production_order WHERE production_order_number = ?", orderNo);
    if (!order) { skipped.push({ orderNo, reason: '生产单不存在' }); continue; }
    if (order.approval_status !== '已审批') { skipped.push({ orderNo, reason: '生产单未审批' }); continue; }

    // 2. 匹配工艺路线（通过产品编号）
    const routing = await query(
      "SELECT * FROM routing_header WHERE item_number = ? AND condition = '启用' AND approval_status = '已审批'",
      order.item_number
    );
    if (!routing) { skipped.push({ orderNo, reason: '未匹配到已审批且启用的工艺路线' }); continue; }

    // 3. 读取工艺路线明细
    const details = await query(
      "SELECT * FROM routing_detail WHERE process_route_number = ? ORDER BY step_number",
      routing.process_route_number
    );
    if (details.length === 0) { skipped.push({ orderNo, reason: '工艺路线无工序明细' }); continue; }

    // 4. 逐条生成工序任务
    let tasksGenerated = 0;
    for (const detail of details) {
      const taskNumber = await generateTaskNumber(); // PT-YYYYMMDD-NNN

      await query(`
        INSERT INTO process_task (
          process_task_number, production_order_number, production_number,
          process_route_number, step_number,
          item_number, item_name, specifications, basic_unit, planned_quantity,
          completed_quantity,
          standard_process_number, standard_process_name,
          work_center_number, work_center_name,
          process_material_input_number, process_material_input_quantity,
          process_material_input_unit, material_wastage_rate,
          excess_reporting_ratio, ingredient_addition_method,
          task_status, approval_status, creation_date, creation_man
        ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, 0, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, '未开始', '草稿', GETDATE(), ?)
      `, [
        taskNumber, order.production_order_number, order.production_number,
        routing.process_route_number, detail.step_number,
        order.item_number, order.item_name, order.specifications, order.basic_unit, order.planned_quantity,
        detail.standard_process_number, detail.standard_process_name,
        detail.work_center_number, detail.work_center_name,
        detail.process_material_input_number, detail.process_material_input_quantity,
        detail.process_material_input_unit, detail.material_wastage_rate,
        detail.excess_reporting_ratio, detail.ingredient_addition_method,
        currentUser
      ]);
      tasksGenerated++;
    }

    results.orderCount++;
    results.taskCount += tasksGenerated;
    results.details.push({ production_order_number: orderNo, tasks_generated: tasksGenerated });
  }

  return results;
}
```

### 7.2 匹配规则优先级

当同一产品编号存在多条工艺路线时：

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 1 | condition = '启用' AND approval_status = '已审批' | 必须条件 |
| 2 | creation_date DESC | 取最新创建的工艺路线 |
| 3 | 仅取第一条匹配结果 | 避免重复拆解 |

### 7.3 防重复机制

| 策略 | 说明 |
|------|------|
| 检查已存在 | 插入前检查 process_task 中是否已存在相同 production_order_number + step_number 的记录 |
| 跳过重复 | 若已存在则跳过，记入 skipped |
| 用户提示 | 前端显示"已存在N条工序任务，将跳过重复" |

## 十、与其他模块的关联

### 10.1 上游模块

| 模块 | 关联方式 | 说明 |
|------|---------|------|
| 生产单 | production_order_number | 工序任务从生产单拆解生成 |
| 工艺路线主表 | process_route_number + item_number | 通过产品编号匹配工艺路线 |
| 工艺路线明细 | step_number | 每条工序明细对应一条工序任务 |
| 生产计划 | production_number | 间接关联（通过生产单） |

### 10.2 下游模块

| 模块 | 关联方式 | 说明 |
|------|---------|------|
| 报工单 | process_task_number | 每次报工关联到具体工序任务 |
| 领料单 | process_task_number | 按工序任务发放物料 |

### 10.3 业务链完整流程

```
生产计划 (Production_plan)
    ↓  从计划导入
生产单 (production_order)
    ↓  审批通过后
    ↓  匹配工艺路线 (routing_header + routing_detail)
    ↓  按工序拆解
工序任务单 (process_task)  ← 【本模块】
    ↓  审批通过后
    ├→ 报工单 (work_report)     → 回写 completed_quantity
    └→ 领料单 (material_issue)  → 按工序发放物料
```

## 十一、典型业务场景

### 场景1：完整生产流程

1. 创建生产计划 → 审批
2. 从计划导入生成生产单 → 审批
3. 打开工序任务管理 → 点击"从生产单导入"
4. 选择已审批的生产单 → 系统自动匹配工艺路线
5. 生成 N 条工序任务（每道工序一条）→ 审批
6. 车间按工序任务执行生产 → 报工
7. 报工回写完成数量 → 任务状态自动更新

### 场景2：查看某张生产单的所有工序

1. 在工序任务管理页面，使用搜索框输入生产单编号
2. 或通过生产单编号筛选器精确过滤
3. 表格显示该生产单拆解的所有工序任务，按工序序号排序
4. 可查看每道工序的进度（完成率）

### 场景3：按工作中心查看待执行任务

1. 选择工作中心筛选器
2. 选择任务状态 = "未开始" 或 "进行中"
3. 表格显示该工作中心待执行的所有工序任务
4. 便于车间主任安排当日生产
