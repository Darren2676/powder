2.2 plan_status（计划状态）— 全链路核心状态

未开始 → 已派发 → 已备料 → 生产中 → 已完成
变化触发操作回写销售明细代码位置
未开始 → 已派发 dispatchAndGenerateCore — 派发生成工序任务+备料单+委外申请 production_status → '计划中' dispatch.ts L205
已派发 → 已备料 首道工序物料全部领完（领料出库回调） production_status → '待生产' materialIssue.controller.ts L467
已备料 → 已派发 撤回领料后首道工序不再全部领完 — materialIssue.controller.ts L855 / materialReturn.controller.ts L348
已派发 → 已备料 退料后再领料，首道又全部齐套 — materialReturn.controller.ts L572
已备料 → 生产中 首次报工（syncTaskCompletion检测 qtyDelta > 0） production_status → '生产中' taskSync.ts L62
生产中 → 已完成 所有工序 task_status IN (已完成,已关闭) 且 inspect_status IN (检验合格,无需检,已处理) production_status → '生产完成' + 触发自动入库 taskSync.ts L77-93
已完成 → 生产中 撤销重报删除末道报工，但仍有前道报工记录 —（单向递进不回退） taskSync.ts L39-41（completed>0且
生产中 → 已备料/已派发 撤销重报删除全部报工，completed 归零 —（单向递进不回退） taskSync.ts L44-48（completed≤0 → 未开始）
关键校验：派发前必须 approval_status='已审批' 且 plan_status='未开始'（dispatch.ts L192-197）。

2.3 inbound_status（入库状态）— 独立于 plan_status 流转

未入库 → 部分入库 → 全部入库
变化触发操作代码位置
未入库 → 部分入库首次生产入库确认finishedGoods.ts L117
部分入库 → 全部入库累计入库量 >= 计划量finishedGoods.ts L117
全部入库/部分入库 → 未入库入库撤回material.ts L526
说明：生产单可多次分批入库。inbound_status 独立于 plan_status 流转，互不阻塞。入库确认触发倒冲扣减+成品库存流水+会计期间匹配。

源码位置：server/src/services/orderDispatch/dispatch.ts、server/src/services/workReport/taskSync.ts

四、Sales_order_detail — 销售订单明细 production_status

4.1 单向递进链路

未加入计划 → 待排产 → 计划中 → 待生产 → 生产中 → 生产完成
核心原则：单向递进，永不回退。syncProductionStatus 使用等级排序实现：
未加入计划(0) < 待排产(1) < 计划中(2) < 待生产(3) < 生产中(4) < 生产完成(5)
newRank <= currentRank 时跳过更新（salesOrderSync.service.ts L85）。
变化等级触发来源回写函数
→ 待排产1MPS从销售订单导入生产计划mps.controller.ts L452
→ 计划中2生产单派发（plan_status='已派发'）syncProductionStatus(orderNo, '计划中')
→ 待生产3首道备料完成（plan_status='已备料'）syncProductionStatus(orderNo, '待生产')
→ 生产中4首次报工（plan_status='生产中'）syncProductionStatus(orderNo, '生产中')
→ 生产完成5所有工序完成（plan_status='已完成'）syncProductionStatus(orderNo, '生产完成')

4.2 回写链路

数据流：
production_order.production_number → Production_plan.production_number
→ Production_plan.source_order_number + source_line_number
→ sales_order_detail.sales_order_number + line_number
→ 确认 source_order_number 真实存在于 sales_order 表中（排除预测单等非销售来源）

源码位置：server/src/services/salesOrderSync.service.ts L38-95

重要约束：sales_order_detail.production_status 采用单向递进机制，永不回退。即使生产单因撤销重报/返修回退到「生产中」或「已备料」，销售明细的生产状态仍保持「生产完成」不变。这确保了销售端数据不会被后端操作污染。
