# 工艺路线管理方案

## 一、系统概述

工艺路线管理模块是 Seals MES System 的核心生产数据模块，包含两大部分：

- **工艺路线（Routing）**：基础工艺路线数据管理，单表平铺结构
- **工艺路线主从表（RoutingMaster）**：主表 + 工序明细的主从结构，集成审批流程

## 三、后端 API 接口

### 3.1 基础工艺路线接口 (/routings)

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /routings | 获取列表（支持分页、搜索） | 登录用户 |
| POST | /routings | 创建工艺路线 | 登录用户 |
| PUT | /routings/:id | 更新工艺路线 | 登录用户 |
| DELETE | /routings/:id | 删除工艺路线 | 登录用户 |
| GET | /routings/export | 导出 Excel | 登录用户 |
| POST | /routings/import | 导入 Excel | 登录用户 |

**查询参数：**
- `page`: 页码（默认 1）
- `limit`: 每页数量（默认 20）
- `search`: 模糊搜索（编号/名称/产品编号）

### 3.2 工艺路线主表接口 (/routing-masters)

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /routing-masters | 获取主表列表 | 登录用户 |
| GET | /routing-masters/:id | 获取详情（含明细） | 登录用户 |
| POST | /routing-masters | 创建主表记录 | 登录用户 |
| PUT | /routing-masters/:id | 更新主表（仅草稿可编辑） | 登录用户 |
| DELETE | /routing-masters/:id | 删除主表（仅草稿可删除） | 登录用户 |
| GET | /routing-masters/export | 导出（含明细） | 登录用户 |
| POST | /routing-masters/import | 导入（含明细） | 登录用户 |

**查询参数：**
- `page`, `limit`, `search`: 同上
- `condition`: 状态筛选（启用/禁用）
- `approval_status`: 审批状态筛选（草稿/待审批/已审批）

**创建时服务端自动设置：**
- `creation_date`: 当前日期时间
- `creation_man`: 当前登录用户名
- `approval_status`: "草稿"

### 3.3 工序明细接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /routing-masters/:headerId/details | 获取工序明细列表 |
| POST | /routing-masters/:headerId/details | 新增工序明细 |
| PUT | /routing-masters/details/:detailId | 更新工序明细 |
| DELETE | /routing-masters/details/:detailId | 删除工序明细 |

**工序序号自动生成逻辑：**
- 若 `step_number` 为空，查询当前最大工序号 + 10
- 示例：现有 10, 20, 30 -> 新增自动设为 40

### 3.4 审批流程接口 (/approval)

| 方法 | 路径 | 说明 | 权限 | 状态转换 |
|------|------|------|------|---------|
| POST | /approval/submit | 提交审批 | 登录用户 | 草稿 -> 待审批 |
| POST | /approval/approve | 审批通过 | manager/admin | 待审批 -> 已审批 |
| POST | /approval/reverse | 反审退回 | manager/admin | 已审批 -> 草稿 |
| POST | /approval/withdraw | 撤回提交 | 提交人 | 待审批 -> 草稿 |
| GET | /approval/log | 获取审批日志 | 登录用户 | - |

**请求体格式：**
```json
{
  "module": "routing_header",
  "record_id": "RTM001",
  "remark": "可选备注"
}
```

## 四、审批流程设计

### 4.1 状态机

```
        ┌─────────┐   提交审批    ┌──────────┐
        │  草 稿   │ ────────────→ │  待审批   │
        └─────────┘               └──────────┘
             ↑                         │
             │                       审批通过
             │                         ↓
             │                    ┌──────────┐
             └─────── 反审 ────── │  已审批   │
                                  └──────────┘

        ┌──────────┐  撤回提交    ┌─────────┐
        │  待审批   │ ────────────→ │  草 稿   │
        └──────────┘  (仅提交人)   └─────────┘
```

### 4.2 操作权限矩阵

| 操作 | 前置状态 | 权限要求 | 附加条件 |
|------|---------|---------|---------|
| 提交审批 | 草稿 | 登录用户 | 无 |
| 审批通过 | 待审批 | manager / admin | 无 |
| 反审退回 | 已审批 | manager / admin | 无 |
| 撤回提交 | 待审批 | 登录用户 | 仅限提交人本人 |

### 4.3 审批联动行为

| 操作 | 触发行为 |
|------|---------|
| 提交审批 | 记录审批日志 + 通知所有 manager/admin |
| 审批通过 | 记录审批日志 + 通知提交人 |
| 反审退回 | 记录审批日志 + 通知原创建人 |
| 撤回提交 | 记录审批日志 |

### 4.4 审批对编辑/删除的约束

- **草稿**：可编辑、可删除
- **待审批**：不可编辑、不可删除（前端按钮禁用 + 后端校验拦截）
- **已审批**：不可编辑、不可删除（前端按钮禁用 + 后端校验拦截）

### 5.3 审批组件

**ApprovalStatusTag** - 审批状态标签：
- 草稿 -> 灰色(default)
- 待审批 -> 蓝色(processing)
- 已审批 -> 绿色(success)

**ApprovalActions** - 审批操作按钮组：
- 提交审批：草稿状态显示
- 审批通过：待审批 + manager/admin 显示
- 撤回：待审批状态显示
- 反审：已审批 + manager/admin 显示
- 所有操作均弹出确认框，支持填写备注

**ApprovalLogModal** - 审批历史弹窗：
- 时间轴形式展示所有审批记录
- 每条记录包含：操作类型、操作人、时间、状态转换、备注
- 操作图标：提交(蓝) / 审批(绿) / 反审(橙) / 撤回(灰)

### 5.4 自动填充逻辑

选择关联数据时自动填充对应名称：
- 产品编号 -> 产品名称
- 标准工序编号 -> 标准工序名称
- 后置工序编号 -> 后置工序名称
- 工作中心编号 -> 工作中心名称
- 仓库编号 -> 仓库名称

## 六、导入导出设计

### 6.1 导出

**基础工艺路线：** 直接导出 routing 表全部字段

**主从表导出：** 关联查询 routing_header + routing_detail，按 process_route_number 和 step_number 排序，Excel 列顺序：
工艺路线编号, 工艺路线名称, 产品编号, 产品名称, 生产自动入库规则, 状态, 工序序号, 标准工序编号, 标准工序名称, 后置工序编号, 后置工序名称, 工作中心编号, 工作中心名称, 超额报工比例, 配料方式, 工序物料投入编号, 工序物料投入数量, 工序物料投入单位, 物料损耗率, 倒冲, 默认仓库

### 6.2 导入

**处理逻辑：**
1. 读取 Excel 文件，解析每行数据
2. 按 process_route_number 分组
3. 对每个分组：
   - 检查 routing_header 是否已存在
   - 若不存在：插入新 header（approval_status = 草稿）
   - 插入所有 detail 记录（跳过无效行）
4. 使用数据库事务保证原子性
5. 返回导入统计（header 数 + detail 数）

## 七、错误处理

| 错误场景 | HTTP 状态码 | 处理方式 |
|---------|------------|---------|
| 工艺路线编号重复 | 400 | 提示"编号已存在" |
| 非草稿状态编辑/删除 | 403 | 提示"已提交审批或已审批的记录不允许编辑" |
| 非待审批状态审批 | 400 | 提示"当前状态不允许审批" |
| 非提交人撤回 | 403 | 提示"只有提交人可以撤回" |
| 导入文件为空 | 400 | 提示"Excel 文件内容为空" |
| 导入格式错误 | - | 跳过该行，继续处理，最后统计成功数 |

## 十、典型业务场景

### 场景1：新建并提交审批

1. 用户点击"新建"，填写工艺路线信息，保存（状态：草稿）
2. 添加工序明细（选中主表行后在下方添加）
3. 确认无误后点击"提交审批"（状态：草稿 -> 待审批）
4. 系统自动通知所有 manager/admin 角色用户
5. 审批人登录，在审批状态筛选中选择"待审批"查看
6. 点击"审批通过"（状态：待审批 -> 已审批）
7. 系统通知提交人审批结果

### 场景2：反审修改后重新提交

1. 审批人发现问题，点击"反审"（状态：已审批 -> 草稿）
2. 原创建人收到通知，编辑修改工艺路线内容
3. 修改完成后重新"提交审批"（状态：草稿 -> 待审批）

### 场景3：批量导入

1. 用户准备符合模板格式的 Excel 文件
2. 点击"导入"选择文件上传
3. 系统按工艺路线编号分组，创建主表 + 明细
4. 所有导入记录初始状态为"草稿"
5. 返回导入统计结果
